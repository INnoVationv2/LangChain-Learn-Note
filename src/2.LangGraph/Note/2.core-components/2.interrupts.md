# interrupts

`interrupt()` 依赖 Checkpointer 保存状态。触发中断后，图暂停执行；恢复时，会从被中断节点的开头重新执行，因此该节点中 `interrupt()` 之前的代码也会再次执行。

```ts
const nodeB = async (state: typeof stateSchema.State) => {
  // interrupt恢复后, 从头执行
  ......
  interrupt("Continue?");
  ......
}
```

可以将任何可序列化的 JSON 值作为resume值传入.

**验证输入Demo**

```ts
const State = new StateSchema({
  age: z.number().nullable(),
  pendingQuestion: z.string().nullable(),
});

const builder = new StateGraph(State)
.addNode("collectAge", (state) => {
  const question = state.pendingQuestion ?? "What is your age?";
  const answer = interrupt(question); // called exactly once per invocation
  if (typeof answer === "number" && answer > 0)
    return { age: answer, pendingQuestion: null };
  return { pendingQuestion: `'${answer}' is not a valid age. Please enter a positive number.` };
})
.addEdge(START, "collectAge")
// 注意看这里
.addConditionalEdges("collectAge", (state) =>
state.age !== null ? END : "collectAge");
```

## 1. interrupt规则

以下是使用interrupts需要遵循的一些规则。

### 1. 不要用 `try/catch` 包裹 `interrupt()`

`interrupt()` 通过抛出特殊异常暂停执行。如果异常被捕获，中断就无法传递给图。

应将中断与可能报错的代码分开, 避免吞掉中断异常。

```ts
const nodeA: GraphNode<typeof State> = async (state) => {
  const name = interrupt("你叫什么名字？");

  try {
    await fetchData();
  } catch (err) {
    console.error(err);
  }
  return state;
};
```

错误示例：

```ts
async function nodeA(state: State) {
  try {
    const name = interrupt("你叫什么名字？");
  } catch (err) {
    console.error(err); // 吞掉了中断异常
  }
  return state;
}
```

### 2.保持节点内的中断顺序一致

节点恢复时会从头执行。LangGraph 为当前任务保存一组恢复值，并**按调用顺序**进行匹配，因此每次中断执行的顺序必须一致。

```ts
async function nodeA(state: State) {
  const name = interrupt("你叫什么名字？");
  const age = interrupt("你多大了？");
  const city = interrupt("你住在哪个城市？");
  return { name, age, city };
}
```

不要因条件变化而跳过中断，否则恢复值可能匹配到错误的调用：

```ts
const nodeA: GraphNode<typeof State> = async (state) => {
  const name = interrupt("你叫什么名字？");

  // 如果条件在恢复时变化，中断顺序就会改变
  if (state.needsAge)
    const age = interrupt("你多大了？");

  const city = interrupt("你住在哪个城市？");
  return { name, city };
};
```

不要在执行次数不确定的循环中调用 `interrupt()`，比如使用 `while (true)` 输入校验循环。应使用条件边实现校验流程。

### 3.传入可 JSON 序列化的数据

传给 `interrupt()` 的值应是字符串、数字、布尔值，或由简单值组成的对象、数组。避免函数、类实例等复杂对象，以兼容不同 Checkpointer。

```ts
const nodeA: GraphNode<typeof State> = async (state) => {
  const name = interrupt("你叫什么名字？");
  const count = interrupt(42);
  const approved = interrupt(true);
  return { name, count, approved };
};
```

错误示例：

```ts
function validateInput(value: string): boolean { return value.length > 0; }

const nodeA: GraphNode<typeof State> = async (state) => {
  const response = interrupt({
    question: "你叫什么名字？",
    validator: validateInput // 函数无法 JSON 序列化
  });
  return { name: response };
};
```

### 4.中断前的代码应具有幂等性

恢复时，节点会重新执行，因此中断前的数据库写入、API 调用等也会重复执行。

建议:

- 中断前使用幂等操作。
- 将这些代码放到中断之后。
- 拆分代码到独立节点。

```ts
const nodeA: GraphNode<typeof State> = async (state) => {
  // 按 userId 更新或插入，重复执行不会新增重复用户
  await db.upsertUser({
    userId: state.userId,
    status: "pending_approval"
  });

  const approved = interrupt("是否批准此变更？");
  return { approved };
};
```

不要在中断前无条件创建记录，否则每次恢复都可能产生重复数据：

```ts
const nodeA: GraphNode<typeof State> = async (state) => {
  const auditId = await db.createAuditLog({
    userId: state.userId,
    action: "pending_approval",
    timestamp: new Date()
  });

  const approved = interrupt("是否批准此变更？");
  return { approved, auditId };
};
```

### 5.在节点中调用子图

父Node调用了子图，子图中有3个Node, 其中第二个触发了`interrupt`。

分析此时状态: 父node没有执行完成。子图第一个Node执行完成, 第二个没有执行完成

因此, 恢复的时候，父node 在`call subgraph`之前的代码会重复执行。子图的第一个 node不会执行，第二个node`interrupt()`之前的代码会重复执行。

```
ParentNode
├── 写数据库         ⚠️重复执行
├── 调用 API				 ⚠️重复执行
└── Call Subgraph
			└── Sub NodeA  ⚠️不会执行
      └── Sub NodeB
           ├── 写数据库  ⚠️重复执行
           └── interrupt()
```

### 6.用静态中断调试

静态中断可在节点执行前后设置断点，逐个节点执行, 仅适用于调试和测试 

```ts
const graph = builder.compile({
  interruptBefore: ["node_a"],
  interruptAfter: ["node_b", "node_c"],
  checkpointer
});
```

- `interruptBefore`：在指定节点执行前暂停。
- `interruptAfter`：在指定节点执行后暂停。
- 静态断点需要 Checkpointer，恢复时使用同一 `thread_id`。
