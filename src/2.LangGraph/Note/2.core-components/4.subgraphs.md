# 子图

添加子图时，需定义父图与子图的通信方式：

| 方式                                            | 适用场景                                     | 实现方式                                                 |
| ----------------------------------------------- | -------------------------------------------- | -------------------------------------------------------- |
| **[在节点内调用子图](#1.在节点内调用子图)**     | 父图与子图的State Schema不同，需要进行转换。 | 将父图State映射为子图输入，再将子图输出映射回父图State。 |
| **[将子图作为节点添加](#2.将子图作为节点添加)** | 父图与子图State Schema相同，不误转换         | 将编译后的子图直接传给 `add_node`，无需包装函数。        |

## 1.在节点内调用子图

调用的时候，需要将父图的state中字段传给对应的subgraph state中字段。

```ts
const subgraphState = new StateSchema({
    subState: z.string(),
});

const subgraph = new StateGraph(subgraphState)
    .addNode("subgraphNode1", (state) => {
        return {bar: "hi! " + state.subState};
    })
    .addEdge(START, "subgraphNode1")
    .compile();


const State = new StateSchema({
    state: z.string(),
});

const graph = new StateGraph(State)
    .addNode("node1", async (state) => {
        const subgraphOutput = await subgraph.invoke({subState: state.state});
        return {graphState: subgraphOutput.subState};
    })
    .addEdge(START, "node1")
    .compile();

const output = await graph.invoke({});
console.log(output);
```

## 2.将子图作为节点添加

```ts
const State = new StateSchema({ foo: z.string() });

const subgraph = new StateGraph(State)
    .addNode("subgraphNode1", (state) => {
        return { foo: "hi! " + state.foo };
    })
    .addEdge(START, "subgraphNode1")
    .compile();

const graph = new StateGraph(State)
    .addNode("node1", subgraph)
    .addEdge(START, "node1")
    .compile();
```

## 3.子图的persistence

执行过程中, 若父图多次调用子图, 此时需要决定是否在多次调用之间保留内部数据。例如，客服机器人将任务交给“账单专家”子智能体时，它应该记住客户之前的问题，还是每次重新开始？

`.compile()` 的 `checkpointer` 参数控制子图的持久化方式：

| 模式           | `checkpointer` 值 | 行为                                                         |
| -------------- | ----------------- | ------------------------------------------------------------ |
| **每次调用**   | `None`（默认）    | 每次调用重新开始，继承父图的checkpointer，支持单次调用内的中断和持久。 |
| **按线程保留** | `True`            | 同一线程内的状态跨调用累积，每次从上次状态继续。             |
| **无状态**     | `False`           | 不保存检查点，像普通函数一样运行，不支持中断或持久执行。     |

**每次调用独立**适合大多数应用，包括子智能体处理独立请求的多智能体系统。

**按线程保留**适合需要多轮对话记忆时，例如通过多次交流积累上下文的研究助手。

### 按线程保留

具体见[底层解析](#checkpoint=true底层解析)

> 开启 checkpoint=true 后，最大的变化是在保存 checkpoint ID 的时候，会把所有的 checkpoint ID 保存到一个 namespace 里面. 

在子图设置`checkpointer=True`，使其拥有自己的检查点历史记录。这会在子图的每个步骤创建检查点.

```ts
const subgraph = new StateGraph(StateAnnotation)
  .addNode("stepA", stepA)
  .addNode("stepB", stepB)
  .addEdge(START, "stepA")
  .addEdge("stepA", "stepB")
  .compile({ checkpointer: true }); // 开启子图检查点

//或者
const fruitAgent = createAgent({
  model: "gpt-5.4-mini",
  tools: [fruitInfo],
  prompt: "You are a fruit expert. Use the fruit_info tool. Respond in one sentence.",
  checkpointer: true,
});
```

### 无状态

如果想像普通函数调用一样运行子代理，且不涉及检查点开销时，请使用`checkpointer=False`选项。子图无法暂停/恢复。

```ts
const subgraph = new StateGraph(StateAnnotation)
  .addNode("stepA", stepA)
  .addNode("stepB", stepB)
  .addEdge(START, "stepA")
  .addEdge("stepA", "stepB")
  .compile({ checkpointer: false }); // 开启子图检查点

//或者
const fruitAgent = createAgent({
  model: "gpt-5.4-mini",
  tools: [fruitInfo],
  prompt: "You are a fruit expert. Use the fruit_info tool. Respond in one sentence.",
  checkpointer: false,
});
```

## 4.查看子图状态

```ts
const subgraphState = (await graph.getState(config, { subgraphs: true })).tasks[0].state;
```

## 5.子图Stream输出

```ts
const stream = await graph.streamEvents(
  { foo: "foo" },
  {
    subgraphs: true,
    version: "v3",
  }
);
for await (const snapshot of stream.values) {
  console.log(snapshot);
}
```
