# 向量搜索基础

1. **检索**：从海量文档中筛选出可能相关的文档。
2. **排名**：对候选答案进行排序，使最佳答案排在最前面。

关键词搜索的缺点: 无法搜索词语不同但是意思相近的情况, 比如“car repair” 和 “automobile maintenance.”

## 1.基础概念

### 1.什么是Embedding

`嵌入向量(Embedding)`是一串数字列表，比如`[0.2, -0.5, 0.8, ...]`。语义搜索的工作原理是将文本转换为向量。语义相近的文本生成的向量会接近，而语义不同的文本生成的向量会原理。语义是由所有维度组合而成的, 单个维度没有含义。

> 注: 比如，“苹果”的向量是：
>
> ```
> [0.2, -0.5, 0.8, ...]
> ```
>
> 不能理解成：
>
> - `0.2` 代表颜色。
> - `-0.5` 代表大小。
> - `0.8` 代表味道。
>
> 模型把“苹果”的信息分散在许多数字里，这组数字整体表示苹果。单个数字没有含义, 比较两个词的意思，也要比较整个向量。

### 2.模型大小和向量维度

选择向量化模型时，重点关注两个指标：

- **模型大小**：模型参数数量。较大的模型通常能捕捉更细致的含义，但生成向量需要更多计算资源。
- **向量维度**：每个向量包含的数值数量。维度越高，占用的存储空间越大，搜索时比较向量所需的计算量也越大。

两者有关联，但并不相同。**大的的模型也可以生成低维向量，向量维度高不一定意味着搜索效果更好。**

### 3.余弦相似度

**余弦相似度（Cosine similarity）通过向量夹角衡量相似程度。** 方向越接近，得分越接近 1；方向差异越大，得分越低。不受向量长度影响。对于文本向量，方向比长度更能反映语义，余弦相似度常用于语义搜索。

计算公式为：

\[ \text{余弦相似度}=\frac{\mathbf{a}\cdot\mathbf{b}}{\|\mathbf{a}\|\|\mathbf{b}\|} \]

其中：

- **\(\mathbf{a}\cdot\mathbf{b}\)** 是点积：将两个向量对应位置的数值相乘，再把结果相加。
- **\(\|\mathbf{a}\|\)、\(\|\mathbf{b}\|\)** 是两个向量的长度，也叫模。

点积除以两个向量的长度，就消除了长度的影响，使得分只反映方向之间的夹角。

<img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/cosine-similarity.png" alt="余弦相似度衡量两个向量之间的角度：角度越小，得分越接近 1；不相关的向量得分接近 0；方向相反的向量得分接近 -1。" style="zoom:50%;" />

### 4.距离度量对比

| 度量方式                 | 常见用途                     | 说明                                                         |
| ------------------------ | ---------------------------- | ------------------------------------------------------------ |
| **余弦相似度（Cosine）** | 文本相似度、自然语言处理模型 | 比较向量方向，忽略长度。是文本向量常用的默认选择。           |
| **点积（Dot product）**  | 已归一化为单位长度的向量     | 当所有向量的长度均为 1 时，排序结果与余弦相似度相同。[备注1] |
| **欧氏距离（L2）**       | 图像向量、空间数据           | 测量两个向量之间的直线距离，方向和长度都会影响结果。         |
| **曼哈顿距离（L1）**     | 网格数据、计数类数据         | 将各维度差值的绝对值相加，在文本向量中较少使用。             |

> [备注1]
>
> 向量归一化: 保持方向不变，长度调整为 1。每个数字都除以向量的长度。
>
> 向量 `[3, 4]` 的长度是：
>
> ```
> √(3² + 4²) = 5
> ```
>
> 归一化后：
>
> ```
> [3 ÷ 5, 4 ÷ 5] = [0.6, 0.8]
> ```
>
> 方向没变，长度变成了 1。这样比较向量时，就可以专注于方向的差异。
>
> 
>
> 两个向量：
>
> ```
> A = [0.6, 0.8]
> B = [0,   1  ]
> 
> 点积 = 0.6 × 0 + 0.8 × 1 = 0.8
> ```
>
> 余弦相似度的计算方法是：
>
> ```
> 余弦相似度 = 点积 ÷（A 的长度 × B 的长度）
> ```
>
> 因为A和B的长度都是 1，所以：
>
> ```
> 余弦相似度 = 0.8 ÷（1 × 1）= 0.8
> ```
>
> **因此，向量长度都为 1 时，直接算点积，就能得到余弦相似度。**

### 5.  仅有相似性是不够的

| 词语                       | 余弦相似度 |
| :------------------------- | :--------- |
| “狗咬人” 和 “人咬狗”       | 0.907      |
| “对儿童安全”和“对儿童有害” | 0.779      |
| “狗咬人” 和 “犬类袭击人”   | 0.570      |

语义搜索对于许多同义词和释义词来说效果不错，但仍然会忽略一些重要细节，例如词序和否定。当这些细节至关重要时，不要仅仅依赖相似度。

### 6. 精确匹配(Exact Matching)

并不是所有查询都需要理解语义。例如，查找商品编号 `SKU-48291` 时，需要的是**编号完全一致**。

如果排在第一位的是另一个商品编号，搜索就失败了。这里应该使`payload filter`：查找 `sku` 字段等于 `"SKU-48291"` 的数据，就能找到对应商品，无需生成向量或计算相似度。

| 方式           | 例子                          | 怎么找                                                       |
| -------------- | ----------------------------- | ------------------------------------------------------------ |
| **字段过滤**   | 找 `sku = "SKU-48291"` 的商品 | 检查商品的 `sku` 字段，只保留编号完全一致的商品              |
| **关键词搜索** | 搜“防水背包”                  | 根据商品介绍中“防水”“背包”等词的匹配情况评分排序             |
| **语义搜索**   | 搜“下雨天背东西用的包”        | 根据意思匹配，即使商品介绍没有使用这些原词，也可能找到防水背包 |

> 字段过滤和关键词搜索的区别是：字段过滤判断“要不要”，BM25 判断“有多相关”。
>
> 例如搜索“防水背包”：
>
> - **字段过滤**：要求 `类别 = 背包`、`防水 = 是`。必须同时满足，否则直接排除。
> - **BM25 关键词搜索**：检查商品介绍里“防水”“背包”等词的匹配情况，再评分排序。只匹配部分关键词的商品也可能出现，具体取决于查询设置。
>
> 字段过滤像设定硬性条件，关键词搜索像给匹配程度打分。关键词搜索也能设置“必须包含某词”，因此两者的功能会有重叠。

### 7. 多种搜索方式结合使用

没有一种检索方法能适用于所有查询。搜索系统需要

- 语义搜索查找相关含义，
- 过滤器匹配精确值（例如 SKU），
- 关键词搜索匹配可能影响排名的词条。

**混合搜索**将语义检索与关键词检索结合起来。使用**密集向量**比较语义，使用**稀疏向量**匹配和排序术语(BM25算法等)。

当用户可能按含义或特定词语进行搜索时，结合这两种方法可以返回更相关的结果。

## 2.稀疏搜索、密集搜索和混合搜索

密集搜索能很好地处理同义词，但对于含义仅由一个词元表达的情况，例如序列号，会有所遗漏。

稀疏搜索则恰恰相反。对于精确的词元和特定领域的术语效果很好，但当查询和文档中没有任何相同的词语时，就力不从心。

### 稀疏搜索

<img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/sparse-search.png" alt="一个具有五个加权标记和许多空维度的稀疏向量。" style="zoom:50%;" />

稀疏向量基于词元：每个词元对应一个值, 稀疏向量由两个数组保存

- `indices`：词的编号

- `values`：对应词的权重

比如`Nike Pegasus 40 running shoes`, 对应数组如下, 一共5个词元

```
indices = [1974139272, 24614856, 1784631546, 243905464, 303109060]
values = [1.67, 1.67, 1.67, 1.67, 1.67]
```

### 匹配逻辑

1. 稀疏搜索根据词元进行匹配，但不要求文字完全一致。

例如，两个编号被拆成：

```
SKU-48291 → sku、48291
SKU-48292 → sku、48292
```

`48291` 和 `48292` 是两个不同词元，不会因为数值接近而获得匹配分数。但包含共同词`sku`，所以搜索结果里可能同时出现。

稀疏向量可使用点积进行匹配：对应位置的权重相乘然后相加。相同词对应同一个位置，因此能贡献分数。

例如, 查询"Nike 跑鞋"：

| 词元 | 词元向量值 | 商品 A：Nike 跑鞋 | 商品 B：Adidas 跑鞋 |
| ---- | ---------- | ----------------- | ------------------- |
| Nike | 1.35       | 1.67              | 0                   |
| 跑鞋 | 2.40       | 1.67              | 1.52                |

点积计算：

```
查询与A：1.35×1.67 + 2.40×1.67 + 0×0 ≈ 6.26
查询与B：1.35×0 + 2.40×1.52 + 0×1.52 ≈ 3.65
```

A 的分数更高，因为两个词都匹配；B 只匹配“跑鞋”。

### 结果融合

两种检索完成排名后，应用融合算法来确定最终排名。

<img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/fusion.png" alt="两个排名列表合并，得分相同的排名更高。" style="zoom:50%;" />

常见方法有：

| 策略                           | 怎么融合                             | 什么时候用                                               |
| ------------------------------ | ------------------------------------ | -------------------------------------------------------- |
| **RRF（倒数排名融合）**        | 根据名次计算综合分数，不使用原始分数 | 适合作为默认方案，尤其适合不同搜索方式的分数尺度不一致时 |
| **DBSF（基于分布的分数融合）** | 根据各路分数的分布进行归一化，再合并 | 当分数差距能够反映结果相关性的强弱，希望保留这种差异时   |

> RRF 看“排第几”，DBSF 还会看“领先多少”。
>
> 假设搜索出现下面两种情况：
>
> | 文档 | 密集度评分 | BM25评分 |
> | ---- | ---------- | -------- |
> | A    | 100        | 100      |
> | B    | 99         | 1        |
> | C    | 0          | 0        |
>
> 两种情况的排名都是 **A → B → C**，但含义不同：
>
> - **情况一**：A、B 几乎一样好，C 很差。
> - **情况二**：A 明显领先，B、C 都很差。
>
> **RRF 不看分数。** 它只看“A 第一、B 第二、C 第三”，所以这两种情况对融合结果的贡献完全一样。
>
> DBSF 会考虑分数差距。先把各路搜索的分数调整到可比较的尺度，再合并。因此，它能保留"情况一中B接近 A，情况二中B接近 C"的差别。

### 重排序

**重排序（Reranking）可以让搜索结果排得更准确。** 先用速度较快的方法找出一批候选结果，再用计算成本较高的模型仔细比较这些结果，而不是让模型处理整个资料库。这样既能控制延迟，又能把最相关的内容排到前面。

重排序很适合与**混合搜索**搭配使用。混合搜索通过多种方式查找内容，尽量减少遗漏；重排序再进一步判断这些结果与问题的相关程度。例如，**后期交互模型（Late Interaction Model）**会把问题和文档分别表示为多个向量，从词元层面进行更细致的比较，比单个向量更能捕捉局部的匹配关系。

本教程将介绍如何结合三种向量表示，构建混合搜索引擎：

- **稠密向量**：根据文本含义进行语义搜索。
- **稀疏向量**：根据关键词进行搜索。
- **后期交互向量**：对候选结果进行重排序。

这三种方式相互配合，让搜索引擎返回更相关的结果。
