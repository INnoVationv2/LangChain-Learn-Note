# 检索(retrieval)

**检索增强生成(RAG): ** 根据问题获取相关的外部知识, 然后把这些知识提供给LLM，帮助它生成回答。

RAG解决了两个问题

- **上下文有限**：无法一次读取整个资料库。
- **知识静态**：训练数据截止于某个时间点，无法自动掌握之后的信息。

## 1.**构建知识库**

知识库是检索时使用的文档或结构化数据集合。

如果需要自建知识库，可使用LangChain的文档加载器和向量存储，构建自己的数据知识库。

>  如果已有知识库，如 SQL 数据库、文档数据库、CRM 或内部文档系统，则无需重建，可以：
>
> - **Agentic RAG**：把知识库的查询能力封装成工具，让Agent自行检索。
> - **2-Step RAG**：先检索，再把结果作为上下文交给LLM。

### 1.从检索到 RAG

检索功能使LLM能够在运行时访问相关上下文。还可以更进一步：将检索获取到的结果输入给LLM, 以生成基于上下文的答案。

**检索**：通过向量搜索找到与问题相关的资料。

**RAG**：找到资料后，让模型根据资料生成回答。

## 2.RAG架构

RAG 有多种实现方式，可以根据系统需求选择。下面介绍各类架构。

| 架构                 | 说明                                                         | 可控性 | 灵活性 | 延迟   | 应用示例                     |
| -------------------- | ------------------------------------------------------------ | ------ | ------ | ------ | ---------------------------- |
| **2-Step RAG**       | 流程固定，每次都先查资料，再回答。                           | 高     | 低     | 快     | 常见问题解答、文档问答机器人 |
| **Agentic RAG**      | Agent自己判断是否需要查资料、用什么工具，可能查多次。        | 低     | 高     | 不固定 | 可使用多种工具的研究助手     |
| **Hybrid（混合式）** | 结合固定流程和Agent判断，例如检索后检查资料是否足够，不够就再次检索。 | 中     | 中     | 不固定 | 需要质量验证的专业领域问答   |
```
可控性: 指流程是否固定、容易预测；
延迟: 指等待回答的时长。
```

### 3.Hybrid RAG

结合**两步式 RAG** 和 **Agentic RAG** 的特点，引入查询预处理、检索结果验证、生成后检查等中间步骤。比固定流程更灵活，同时保留一定的执行控制能力。

典型组件包括：

- **优化问题**：把用户的问题改得更清楚，比如补充前文信息，或换几种说法去搜索，让相关资料更容易被找到。

  **检查检索结果**：看找到的资料是否与问题有关、是否足够回答问题。如果不够，就调整问题再查一次。

  **检查答案**：看看答案有没有错误、是否回答完整、是否符合查到的资料。有问题就修改或重新生成。

这些步骤经常会进行多轮迭代

适用场景：

- 用户问题含糊或信息不完整。
- 需要验证或质量控制的系统。
- 涉及多个信息源或需要反复优化的工作流。
