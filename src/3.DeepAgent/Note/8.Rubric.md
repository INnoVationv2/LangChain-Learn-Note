# Grading rubrics(评分标准)

RubricMiddleware允许你将**完成**的标准定义为一个评分标准，让代理进行自我评估和迭代，直到满足该评分标准或达到配置的最大迭代次数。

**LLM-as-a-judge**是一种模式，一个LLM根据预定义的标准评估另一个模型的输出.

## 1.配置Middleware

将`RubricMiddleware`添加到`middleware=`中

```ts
agent = create_deep_agent(
    model='model1',
    middleware=[
        RubricMiddleware(
            model="model2",
            max_iterations=3,
        ),
    ],
    checkpointer=InMemorySaver(),
)
```

参数:

| 参数             | 必填 | 默认值         | 说明                                                         |
| ---------------- | ---- | -------------- | ------------------------------------------------------------ |
| `model`          | 是   | 无             | 评分使用的聊天模型                                           |
| `system_prompt`  | 否   | 内置评分提示词 | 未提供时，使用默认系统提示词，说明评判结果的格式及可用工具。 |
| `tools`          | 否   | 无             | 评分者在给出结果前可用于收集证据的工具，例如运行测试、统计 token、读取文件。未提供时，仅根据对话记录进行评判。 |
| `max_iterations` | 否   | `3`            | 允许的最大评分轮数，必须是正整数。达到上限仍未判定满足要求时终止. |
| `on_evaluation`  | 否   | 无             | 接收 `invoke()`、`stream()` 还是 `stream_events()`类型参数, 每轮评分结束后都会调用，并传入该轮的 `RubricEvaluation`。可用于日志记录、自定义指标、评估数据集或界面更新。 |

## 2.调用时的规则

调用时传入评分标准字符串（`rubric`），即可启动自我评估循环。

使用 `invoke()` 进行一次阻塞调用；或使用 `stream_events(..., version="v3")` 配合 `CustomTransformer`，通过 `stream.custom` 实时接收评分事件。

**invoke**

```ts
from langchain.messages import HumanMessage

config = {"configurable": {"thread_id": "my-rubric-thread"}}
result = agent.invoke(
    {
        "messages": [HumanMessage("Write a haiku about spring.")],
        "rubric": (
            "- The poem has three lines\n"
            "- Lines follow a 5-7-5 syllable pattern\n"
            "- The theme is spring"
        ),
    },
    config=config,
)
```

**stream_events**

```ts
from langchain.messages import HumanMessage
from langgraph.stream import CustomTransformer

config = {"configurable": {"thread_id": "my-rubric-thread"}}
stream = agent.stream_events(
    {
        "messages": [HumanMessage("Write a haiku about spring.")],
        "rubric": (
            "- The poem has three lines\n"
            "- Lines follow a 5-7-5 syllable pattern\n"
            "- The theme is spring"
        ),
    },
    config=config,
    version="v3",
    transformers=[CustomTransformer],
)

for event in stream.custom:
    event_type = event.get("type")
    if event_type == "rubric_evaluation_start":
        print(
            f"Grading iteration {event['iteration']} "
            f"(run {event['grading_run_id']})"
        )
    elif event_type == "rubric_evaluation_end":
        print(f"Verdict: {event['result']} — {event.get('explanation', '')}")
```

按评分标准进行评估时，会在 `stream.custom` 上发送以下自定义事件：

| 事件                      | 触发时机                   |
| ------------------------- | -------------------------- |
| `rubric_evaluation_start` | 评分者运行前               |
| `rubric_evaluation_end`   | 评分者返回结果或发生异常后 |

两个事件共有的字段：

- `type`：事件名称.
- `grading_run_id`：同一次评分尝试中的所有事件共用的 ID。
- `iteration`：当前评分轮次的索引，从 `0` 开始。

`rubric_evaluation_end` 包含：

- `result`：本轮评分的最终判定。
- `explanation`：评分者给出的说明摘要。
- `criteria`：各项评分标准的判定结果。

## 3.评分裁定

评分子代理会根据评分标准检查回答，并给出以下判定：

| 状态                     | 含义                                                       | 是否重新运行代理 |
| ------------------------ | ---------------------------------------------------------- | ---------------- |
| `satisfied`              | 所有评分标准均通过。                                       | 否               |
| `needs_revision`         | 至少有一项评分标准未通过；评分反馈会被注入，代理再次运行。 | 是               |
| `max_iterations_reached` | 评分标准仍不满足，但已达到 `max_iterations` 上限。         | 否               |
| `failed`                 | 评分者认为评分标准格式有误，或无法进行评估。               | 否               |
| `grader_error`           | 评分子代理自身发生异常，例如请求超时、结构化响应格式错误。 | 否               |

## 4.观察迭代进度

`on_evaluation` 会在每轮评分结束后被调用，收到评分者的判定结果，无论使用 `invoke()` 还是 `stream_events()`。

如果没有通过 `CustomTransformer` 读取 `stream.custom` 中的评分事件，也没有用LangSmith追踪运行过程，`on_evaluation`回调就是查看评分过程的主要方式。

```ts
def log_evaluation(ev: RubricEvaluation) -> None:
    print(f"iteration {ev['iteration']}: {ev['result']} — {ev['explanation']}")


agent = create_deep_agent(
    model="google_genai:gemini-3.6-flash",
    middleware=[
        RubricMiddleware(
            model="google_genai:gemini-3.6-flash",
            on_evaluation=log_evaluation,
        ),
    ],
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "rubric-eval-session"}}

agent.invoke(
    {"messages": 
     [HumanMessage("Write a one-sentence summary of photosynthesis.")],
     "rubric": (
       "- The answer is one sentence\n"
       "- The answer mentions light and chlorophyll"
     ),
    },
  config=config,
)
```

每次评分者提交评分后会调用`on_evaluation`函数，并传入一个`RubricEvaluation`字典。该字典包含：

| 字段             | 类型   | 说明                                                         |
| ---------------- | ------ | ------------------------------------------------------------ |
| `grading_run_id` | `str`  | 一次评分流程的 ID，流程中的每轮评分共用这个 ID。传入新的 `rubric`，或在上一次评分流程结束后再次使用相同的 `rubric` 调用，都会开始新的评分流程。 |
| `iteration`      | `int`  | 本次运行时第几轮评分，从 `0` 开始。                          |
| `result`         | `str`  | 本轮评分结果：`satisfied`、`needs_revision`、`failed` 或 `grader_error`。 |
| `explanation`    | `str`  | 评分者对本轮结果的说明。如果评分过程出错，会包含异常类型和错误信息。 |
| `criteria`       | `list` | 各项评分标准的检查结果。通过时为 `{name, passed: true}`；未通过时为 `{name, passed: false, gap}`，其中 `gap` 说明需要改进什么。 |

##  5.评分通过事件

**每轮评分的回调行为**

| 情况                 | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| **评分成功完成**     | 每评完一轮，就调用一次 `on_evaluation`，把这一轮的结果告诉你。无论结果是`needs_revision`, `satisfied`还是`failed`. |
| **评分者发生异常**   | 回调收到 `result: "grader_error"`，`explanation` 中包含错误说明，`criteria` 为空列表。 |
| **回调自身发生异常** | 异常会被记录并忽略，评分循环继续执行。不要通过 `on_evaluation` 控制流程，例如在回调中抛出异常来停止代理。 |

如果评分者认为还需要修改，但已经达到 `max_iterations` 上限：

- 回调中的 `result` 仍然是 `"needs_revision"`.表示仍需修改
- 整个流程的最终状态是 `max_iterations_reached`，保存在私有状态 `_rubric_status` 中，不会写入本轮评估记录。
- 要判断是否因达到上限而结束，可在 `invoke()` 完成后检查 `_rubric_status`，也可以结合 `_rubric_evaluations` 的最后一条记录和 `_rubric_iterations` 判断。

## 6.在后续调用中沿用评分标准

如果希望后续调用继续沿用之前的评分标准，可配置检查点（`checkpointer`），并在每次调用时传入相同的 `thread_id`。

发生`KeyboardInterrupt`、`asyncio.CancelledError` 等中断异常时不会捕获，而是直接向外抛出。如果启用了检查点，下次使用相同的评分标准调用时，会继续未完成的评分流程。
