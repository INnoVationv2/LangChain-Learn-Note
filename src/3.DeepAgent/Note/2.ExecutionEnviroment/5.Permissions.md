# Permission

使用声明式权限规则控制Agent可以读取或写入哪些文件和目录。将规则列表传递给`permissions=`，Agent内置的文件系统工具将遵循这些规则。

仅适用于内置文件系统工具(ls、read_file、glob、grep、write_file、edit_file)。自定义Tool和访问文件系统的 MCP Tool不受此权限限制。也不适用于沙箱后端，沙箱可通过`execute`执行任意命令。

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
```

## 1.Permission结构

每条 `FilesystemPermission` 权限规则包含三个字段：

| 字段         | 类型                   | 说明                                                         |
| ------------ | ---------------------- | ------------------------------------------------------------ |
| `operations` | `("read" | "write")[]` | 此规则适用于以下操作: 1.`read` 包括 `ls`、`read_file`、`glob`、`grep`. 2.`write` 包括 `write_file`、`edit_file`。 |
| `paths`      | `string[]`             | 匹配文件路径的 Glob 模式，如 `["/workspace/**"]`。支持 `**` 递归匹配、`{a,b}` 匹配多个选项。 |
| `mode`       | `"allow" | "deny"`     | 允许或拒绝匹配的操作，默认为 `"allow"`。                     |

规则按顺序匹配，第一个`operations`和`paths`与当前调用匹配的规则决定结果。如果没有规则匹配，默认允许调用。

路径必须是绝对路径（以 `/` 开头），不能包含 `..` 或 `~`。无效路径会在创建智能体时抛出错误。

## 2.案例

### 1.隔离工作区目录

仅允许在/workspace/目录下进行读写操作，拒绝其他所有操作：

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["read", "write"],
      paths: ["/workspace/**"],
      mode: "allow",
    }, {
      operations: ["read", "write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
```

### 2.保护特定文件

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["read", "write"],
      paths: ["/workspace/.env", "/workspace/examples/**"],
      mode: "deny",
    }, {
      operations: ["read", "write"],
      paths: ["/workspace/**"],
      mode: "allow",
    }, {
      operations: ["read", "write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
if (!agent) throw new Error("protect-files: agent not created");
```

### 3.Memory只读

允许Agent读取Memory文件，禁止修改. 有些策略或知识库只能由应用程序代码更新。有关更多信息，请参阅只读内存与可写内存。

```ts
const store = new InMemoryStore();
const agent = createDeepAgent({
  model,
  backend: new CompositeBackend(new StateBackend(), {
    "/memories/": new StoreBackend({
      namespace: (rt) => [rt.serverInfo.user.identity],
    }),
    "/policies/": new StoreBackend({
      namespace: (rt) => [rt.context.orgId],
    }),
  }),
  permissions: [
    {
      operations: ["write"],
      paths: ["/memories/**", "/policies/**"],
      mode: "deny",
    },
  ],
  store,
});
```

### 4.拒绝所有访问

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["read", "write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
```

### 5.规则排序

规则顺序至关重要。应将更具体的规则放在更宽泛的规则之前：

```ts
const correctPermissions: FilesystemPermission[] = [
  { operations: ["read", "write"], paths: ["/workspace/.env"], mode: "deny" }, 
  {
    operations: ["read", "write"],
    paths: ["/workspace/**"],
    mode: "allow",
  },
  { operations: ["read", "write"], paths: ["/**"], mode: "deny" },
];

const incorrectPermissions: FilesystemPermission[] = [
  {
    operations: ["read", "write"],
    paths: ["/workspace/**"],
    mode: "allow",
  },{
    operations: ["read", "write"],
    paths: ["/workspace/.env"],
    mode: "deny",
  },
  { operations: ["read", "write"], paths: ["/**"], mode: "deny" },
];
```

## 3.subAgent权限

subAgent默认继承父Agent的权限。要为子代理赋予不同的权限，在规范中设置`permissions`字段。将替换父代理的规则。

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [
    {
      operations: ["read", "write"],
      paths: ["/workspace/**"],
      mode: "allow",
    },
    { operations: ["read", "write"], paths: ["/**"], mode: "deny" },
  ],
  subagents: [
    {
      name: "auditor",
      description: "Read-only code reviewer",
      systemPrompt: "Review the code for issues.",
      permissions: [
        { operations: ["write"], paths: ["/**"], mode: "deny" },
        { operations: ["read"], paths: ["/workspace/**"], mode: "allow" },
        { operations: ["read"], paths: ["/**"], mode: "deny" },
      ],
    },
  ],
});
if (!agent) throw new Error("subagent: agent not created");
```

要授予子代理无限制访问权限，可设置permissions: []。空数组会覆盖父代理的规则，不设任何限制。省略permissions则继承父代理的规则。

## 4. 复合后端

使用 `CompositeBackend` 且默认后端为沙箱时，所有权限路径必须位于已注册的路由前缀下。

沙箱支持执行任意命令，仅靠路径权限无法阻止通过 Shell 访问文件系统，因此需要将权限限定到具体路由对应的后端。

```ts
const sandbox = new StateBackend();
const memoriesBackend = new StateBackend();
const composite = new CompositeBackend(sandbox, {
  "/memories/": memoriesBackend,
});

const agent = createDeepAgent({
  model,
  backend: composite,
  permissions: [
    { operations: ["write"], paths: ["/memories/**"], mode: "deny" },
  ],
});
```

权限中包含任何路线之外的路径，会在施工时触发：

```ts
const sandbox = new StateBackend();
const memoriesBackend = new StateBackend();
const composite = new CompositeBackend(sandbox, {
  "/memories/": memoriesBackend,
});

// /workspace/** 不属于已注册的 /memories/ 路由
createDeepAgent({
  model,
  backend: composite,
  permissions: [
    { operations: ["write"], paths: ["/workspace/**"], mode: "deny" },
  ],
});

// /** 超出了 /memories/ 路由范围
createDeepAgent({
  model,
  backend: composite,
  permissions: [
    { operations: ["read"], paths: ["/**"], mode: "deny" },
  ],
});
```
