# Permission

控制Agent可以读写哪些文件和目录.通过`permissions`参数传入规则

仅适用于内置文件系统Tool(ls、read_file、glob、grep、write_file、edit_file).自定义Tool和访问文件系统的 MCP Tool不受此限制.也不适用于沙箱Backend, 沙箱可通过`execute`执行任意命令.

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
```

## 1.Permission结构

每条permissions规则包含三个字段：

| 字段         | 类型                   | 说明                                                         |
| ------------ | ---------------------- | ------------------------------------------------------------ |
|`operations`|`("read" | "write")[]`| 对以下操作生效: 1.`read`适用于`ls`、`read_file`、`glob`、`grep`. 2.`write`适用于`write_file`、`edit_file`. |
|`paths`|`string[]`| 用于匹配文件路径的通配符模式, 如`["/workspace/**"]`.支持`**`递归匹配、或使用`{a,b}`匹配多个选项. |
|`mode`|`"allow" | "deny"`| 默认为`"allow"`.                     |

规则按顺序匹配, 第一个匹配的规则生效.如果没有规则匹配, 默认允许调用.

路径必须是绝对路径(以`/`开头), 不能包含`..`或`~`.无效路径会在创建Agent时报错.

## 2.案例

### 1.隔离工作区目录

仅允许在`/workspace/`下进行读写操作, 拒绝其他所有操作：

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [{
      operations: ["read", "write"],
      paths: ["/workspace/**"],
      mode: "allow",
    }, {
      operations: ["read", "write"],
      paths: ["/**"],
      mode: "deny",
    }]
});
```

### 2.只读Memory

允许Agent读取Memory文件, 但禁止修改. 有些知识库只能由应用程序代码更新.有关更多信息, 请参阅Memory章节的只读内存与可写内存.

```ts
const store = new InMemoryStore();
const agent = createDeepAgent({
  model,
  backend: new CompositeBackend(new StateBackend(), {
    "/memories/": new StoreBackend({
      namespace: (rt) => [rt.serverInfo.user.identity],
    }),
    "/policies/": new StoreBackend({
      namespace: (rt) => [rt.context.orgId],
    }),
  }),
  permissions: [
    {
      operations: ["write"],
      paths: ["/memories/**", "/policies/**"],
      mode: "deny",
    },
  ],
  store,
});
```

### 3.规则排序

规则顺序至关重要, 将具体的规则放在宽泛的规则之前：

```ts
const correctPermissions: FilesystemPermission[] = [
  { operations: ["read", "write"], paths:
   ["/workspace/.env"], mode: "deny" }, 
  {
    operations: ["read", "write"],
    paths: ["/workspace/**"],
    mode: "allow",
  },
  { operations: ["read", "write"], 
   paths: ["/**"], mode: "deny" },
];
```

## 3.subAgentpermissions

subAgent默认继承父Agent的permissions. 可通过`permissions`字段赋予不同的permissions.

要授予subAgent无限制访问permissions, 可设置`permissions: []`.空数组会覆盖父Agent的规则.

省略permissions会继承父Agent的规则.

```ts
const agent = createDeepAgent({
  model,
  backend,
  permissions: [
    {
      operations: ["read", "write"],
      paths: ["/workspace/**"],
      mode: "allow",
    },
    { operations: ["read", "write"], 
     paths: ["/**"], mode: "deny" },
  ],
  subagents: [
    {
      name: "auditor",
      description: "Read-only code reviewer",
      systemPrompt: "Review the code for issues.",
      // 为subagent赋予不同的规则
      permissions: [
        { operations: ["write"], 
         paths: ["/**"], mode: "deny" },
        { operations: ["read"], 
         paths: ["/workspace/**"], mode: "allow" },
        { operations: ["read"], 
         paths: ["/**"], mode: "deny" },
      ],
    },
  ],
});
if (!agent) throw new Error("subagent: agent not created");
```

## 4.CompositeBackend

使用`CompositeBackend`且默认Backend为沙箱时, 所有Permission的路径必须位于已注册的路由前缀下, permissions中包含任何Backend之外的路径, 都会在Agent创建阶段报错：

```ts
const sandbox = new LocalShellBackend();
const memoriesBackend = new StateBackend();
const composite = new CompositeBackend(sandbox, {
  "/memories/": memoriesBackend,
});

permissions: [
		// 允许
		{ operations: ["write"], 
    paths: ["/workspace/**"], mode: "deny" },
  	// 不允许这么配置, 会报错, /memories/不在/workspace/下
    { operations: ["write"], 
    paths: ["/memories/**"], mode: "deny" },
  ],
```

因为沙箱支持执行任意命令, 仅靠路径permissions无法阻止Shell访问文件系统, 因此需要将permissions限定到具体路由对应的Backend.
