# Backend

Deep Agent通过 `ls`、`read_file`、`write_file`、`edit_file`、`glob` 和 `grep` 等工具，让Agent访问文件系统。这些工具通过**可插拔**的后端(backend)运行。

> `read_file`支持二进制文件(图片、PDF、音频、视频)，返回一个带类型的`content`和 `mimeType` 的 `ReadResult`。
>
> 沙箱和 `LocalShellBackend` 还提供 `execute` 工具，用于执行命令。

## 1.Quickstart

以下是一些内置的文件系统后端：

| 后端                                        | 存储位置与范围                                               | 适用场景                             |
| ------------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| [`StateBackend`(默认)](#1.StateBackend)     | 文件会保存在LangGraph State中；通过 checkpoint在同一线程的多轮对话间保留，不跨线程共享 | 当前任务的临时文件                   |
| [`FilesystemBackend`](#2.FilesystemBackend) | 读写本机磁盘；可通过 `root_dir` 限定根目录, 必须是绝对路径, 通常搭配 `CompositeBackend`，将Agent内部数据(卸载的工具结果、对话历史)与项目文件分开。 | 操作本地项目文件                     |
| `StoreBackend`                              | 使用 LangGraph Store跨线程持久保存文件                       | 长期记忆、通用指令                   |
| `ContextHubBackend`                         | 文件持久化到 LangSmith Hub 仓库，无须另行配置 LangGraph Store | 使用 Hub 保存文件                    |
| Sandbox                                     | 在隔离环境中执行代码，提供文件操作和 `execute`工具           | 运行代码、安装依赖等任务             |
| `LocalShellBackend`                         | 直接在宿主机上访问文件和执行 shell 命令，没有隔离保护，仅适用于受控的开发环境。 | 受控的本地开发环境                   |
| `CompositeBackend`                          | 按路径将文件操作分配给不同后端,例如，默认文件仅限当前线程，`/memories/` 下的文件则跨线程持久保存。 | 同时管理临时文件、项目文件和长期记忆 |

## 2.内置backend

### 1.StateBackend(默认backend)

```ts
import { createDeepAgent, StateBackend } from "deepagents";

// 默认使用StateBackend
const agent = createDeepAgent();
// 等价于
const agent2 = createDeepAgent({
  backend: new StateBackend(),
});
```

工作原理:

1. `StateBackend`将文件存储在当前线程的LangGraph agent state中
2. 通过checkpoint，同一线程上的多个Agent可以保持数据持久化. 文件不会在线程间共享。

最适合:

1. 供Agent记录中间结果的草稿本。
2. 将大型Tool输出自动转存为文件，供Agent分段读取。

注意: 此后端由主Agent与子Agent共享。子Agent写入的文件执行结束后仍保留在LangGraph State中，主Agent和其他子Agent可以继续访问。

### 2.FilesystemBackend

在指定目录下读写**磁盘文件**，让Agent直接访问本地文件系统。

**适用场景：**

- 本地开发 CLI，如编程助手、开发工具。
- CI/CD 流水线。

不适用于 Web 服务器或 HTTP API，应改用 `StateBackend`、`StoreBackend` 或`sandbox`后端。

**安全风险与防护：**

| 风险                                                   | 建议                                              |
| ------------------------------------------------------ | ------------------------------------------------- |
| Agent可读取所有可访问文件，包括 API Key、凭据和 `.env` | 将敏感文件排除在可访问路径之外，尤其是 CI/CD 环境 |
| 配合网络工具时，机密可能通过 SSRF 攻击泄露             | 限制文件与网络访问权限                            |
| 修改会直接保存到磁盘，无法自动撤销                     | 启用人工介入(HITL)中间件，审核敏感操作            |
| 仅设置根目录不能保证访问限制                           | 同时设置 `rootDir` 和 `virtualMode: true`         |

生产环境需要文件操作时，建议使用沙箱后端。默认`virtualMode: false` **即使设置了 `rootDir`，也不提供安全隔离**。

```ts
import { createDeepAgent, FilesystemBackend } from "deepagents";

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new FilesystemBackend({
    rootDir: ".", virtualMode: true})
});
```

**工作方式：**

- Agent可读写`rootDir`目录下的文件。
- `virtualMod:`沙盒模式, 将路径限制在`rootDir`内，阻止 `..`、`~` 和根目录之外的绝对路径。
- 使用安全路径解析，防止不安全的符号链接跳转。可使用ripgrep进行快速grep命令

**建议将FilesystemBackend封装在CompositeBackend中**, DeepAgent会自动将内部数据写入后端：

- `/large_tool_results/`：转存的大型工具结果。
- `/conversation_history/`：对话历史。

如果单独使用`FilesystemBackend`，上述内部文件会写入到实际磁盘的root_dir目录下，导致Agent文件与项目文件混杂在一起。使用`CompositeBackend`将项目目录路由到`FilesystemBackend`，同时将内部路径保留在临时`StateBackend`存储中：

```ts
import { createDeepAgent, CompositeBackend, FilesystemBackend, StateBackend } from "deepagents";

const agent = createDeepAgent({
  backend: new CompositeBackend(
    new StateBackend(), 
    {"/workspace/": new FilesystemBackend({
      rootDir: "/path/to/project",
      virtualMode: true,
    }),
  }),
});
```

这样，Agent在`/workspace/`下的读写操作会写入实际磁盘，而工具结果和其他内部数据则保留在临时状态。

### 3.StoreBackend (LangGraph store)

```ts
import { createDeepAgent, StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph";

const store = new InMemoryStore();

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new StoreBackend({
    namespace: (rt) => [rt.serverInfo.user.identity],
  }),
  store,
});
```

**工作原理**

- 将文件存储在runtime提供的LangGraph BaseStore中，实现跨线程持久存储。

  是否能在进程重启后保留数据，取决于底层 Store；`InMemoryStore` 仅适合本地开发。

**适合**

- 适用于已有 LangGraph Store(如 Redis、Postgres 等实现)的项目，或部署到 LangSmith Deployment 的Agent。

  部署到 LangSmith Deployment 时，可省略 `store`，平台会自动提供。

**通过命名空间隔离数据**

`namespace` 接收一个工厂函数：根据运行时 `Runtime` 返回字符串数组，决定文件存储在哪个命名空间中。

| Runtime 字段       | 提供的信息                                        |
| ------------------ | ------------------------------------------------- |
| `rt.context`       | 调用方通过 context schema 传入的上下文，如用户 ID |
| `rt.serverInfo`    | 服务端信息，如助手 ID、图 ID、已认证用户          |
| `rt.executionInfo` | 执行信息，如线程 ID、运行 ID、检查点 ID           |

```ts
import { StoreBackend } from "deepagents";

// 按用户隔离
const userBackend = new StoreBackend({
  namespace: (rt) => [rt.serverInfo.user.identity],
});

// 按助手隔离：同一助手的所有用户共享
const assistantBackend = new StoreBackend({
  namespace: (rt) => [rt.serverInfo.assistantId],
});

// 按线程隔离
const threadBackend = new StoreBackend({
  namespace: (rt) => [rt.executionInfo.threadId],
});
```

也可以组合多个字段，例如用户 ID + 线程 ID；附加 `"filesystem"` 等后缀，可以区分同一范围下的不同存储用途。

命名空间仅允许字母、数字及 `- _ . @ + : ~`，禁止 `*`、`?`，防止 glob 注入。

如果没有提供namespace工厂，默认使用LangGraph 配置元数据中的`assistant_id`。意味着同一助手的所有用户共享同一个存储空间。对于生产环境的多用户场景，务必提供命名空间工厂。

### 4.ContextHubBackend

将文件系统保存在 LangSmith Context Hub 仓库中，无需单独配置 LangGraph Store。使用前需配置 `LANGSMITH_API_KEY`。

仓库可以是独立仓库，也可以是关联多个技能仓库的Agent仓库：

- Agent仓库保存 `AGENTS.md`、`tools.json` 等顶层配置，挂载在文件系统根目录。
- 关联的技能仓库挂载到 `/skills/` 下，可独立管理版本，并被多个Agent复用。
- 仓库标识支持 `owner/name` 或 `name`。

工作方式与限制：

- 首次使用时拉取仓库，之后从内存缓存读取。
- 写入和编辑会生成 Hub 提交，成功后更新缓存。
- 使用 `parent_commit` 检查并发修改；如果其他写入者已推进版本，需要重新拉取并重试。
- 仓库不存在时，首次读取视为空仓库，首次成功写入可创建仓库。
- `upload_files()` 只接受 UTF-8 文本，其他编码的文件会逐个返回 `invalid_path`。

适合需要持久化文件和提交历史、且主要使用 LangSmith 的工作流。

### 5.LocalShellBackend

直接在宿主机上读写文件、执行 shell 命令，**没有沙箱隔离**。

适用于本地编程助手、可信的个人开发环境，以及妥善管理机密的 CI/CD 流水线。

不适用于生产环境(Web 服务器、API、多租户系统等)、或执行不可信代码。

主要风险：

- 命令拥有当前用户的权限，可读取敏感文件并泄露机密。
- 文件修改和命令执行会直接影响宿主机，无法自动撤销。
- 命令可能无限制地消耗 CPU、内存和磁盘。

**建议采取的防护措施：**

1. 启用人工审核(HITL),  在执行操作前对其进行审查和批准。
2. 仅限在专用开发环境中运行。勿在共享系统或生产系统上使用。
3. 生产环境需要执行 shell 时，使用沙箱.

**启用 shell 后，`virtualMode: true` 也无法提供安全隔离**，shell仍能访问系统中的其他路径。

```ts
import { createDeepAgent, LocalShellBackend } from "deepagents";

const backend = new LocalShellBackend({ workingDirectory: "." });

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend,
});
```

工作方式：

- 在 `FilesystemBackend` 基础上增加 `execute` 工具, 以便在主机上运行 shell 命令。
- 命令直接在本机执行，不经过沙箱。
- 支持`timeout`(默认 120 秒)、`max_output_bytes`(默认 100,000 字节)和环境变量配置。
- Shell命令使用`root_dir`作为工作目录，但仍可访问系统上的任何路径。

### 6.CompositeBackend(router)

按路径前缀分配文件操作，让Agent通过一个文件系统访问不同存储来源。

```ts
import { createDeepAgent, CompositeBackend, StateBackend, StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph";

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new CompositeBackend(new StateBackend(), {
    "/memories/": new StoreBackend({
      namespace: () => ["memories"],
    }),
  }),
  store: new InMemoryStore(),
});
```

此例中：

- `/memories/` 使用 Store，可跨线程访问。
- 其他路径使用 `StateBackend`，仅限当前线程。
- 命名空间固定为 `["memories"]` 没有按用户隔离。
- 列表和搜索结果保留原始路径前缀。

也可将 `/memories/` 路由到记忆存储，将 `/docs/` 路由到自定义文档后端。

### 7.指定后端与协议

- 通过 `createDeepAgent({ backend: ... })` 传入后端，文件系统中间件会使用它执行文件操作；省略时默认使用 `StateBackend()`。

- 后端需实现 `AnyBackendProtocol`，即 `BackendProtocolV1` 或 `BackendProtocolV2`。

**按路径路由到本地磁盘**

下面将 `/memories/` 保存到磁盘，其余路径保留在线程状态中：

```ts
const agent = createDeepAgent({
  backend: new CompositeBackend(new StateBackend(), {
    "/memories/": new FilesystemBackend({
      rootDir: "/deepagents/myagent",
      virtualMode: true,
    }),
  }),
});
```

| Agent访问路径        | 实际存储位置                            |
| -------------------- | --------------------------------------- |
| `/workspace/plan.md` | 当前线程的 `StateBackend`               |
| `/memories/agent.md` | 本地磁盘 `/deepagents/myagent/agent.md` |

路由规则：

- **更长的前缀优先**：`/memories/projects/` 优先于 `/memories/`。
- `ls`、`glob`、`grep` 汇总结果，并保留原始路径前缀。
- 路由到 `StoreBackend` 时，需传入 Store 或由平台提供。
- 大型工具结果、对话历史等内部数据写入默认后端。建议默认使用 `StateBackend`，避免混入磁盘文件或长期存储。
