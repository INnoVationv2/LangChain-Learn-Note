# Backend

Deep Agent通过`ls`、`read_file`、`write_file`等Tool访问文件系统。这些Tool运行在**可插拔**的backend上。

## 1.Backend列表

以下是一些内置的文件系统Backend：

| Backend                                        | 存储位置与范围                                               | 适用场景                             |
| ------------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| [`StateBackend(默认值)`](#1.StateBackend) | 文件保存在LangGraph State中；通过 checkpoint在同一线程的多轮对话间保留，不跨线程共享 | 当前任务的临时文件                   |
| [`FilesystemBackend`](#2.FilesystemBackend) | 读写本机磁盘; 通过`root_dir`限定根目录, 必须是绝对路径, 通常搭配`CompositeBackend`, 将Agent内部数据与项目文件分离。 | 操作本地项目文件                     |
|[`StoreBackend`](#3.StoreBackend)| 使用 LangGraph Store跨线程持久保存文件                       | 长期Memory、通用指令                   |
|[`ContextHubBackend`](#4.ContextHubBackend)| 文件持久化到 LangSmith Hub 仓库，无须另行配置 LangGraph Store | 使用 Hub 保存文件                    |
| Sandbox                                     | 在隔离环境中执行代码，提供文件操作和`execute Tool`| 运行代码、安装依赖等             |
|[`LocalShellBackend`](#5.LocalShellBackend)| 直接在宿主机上访问文件和执行 shell 命令，没有隔离保护，仅适用于受控的开发环境。 | 受控的本地开发环境                   |
|[`CompositeBackend`](#6.CompositeBackend)| 按路径将文件操作分配给不同Backend,例如，默认文件仅限当前线程，`/memories/`下的文件则跨线程持久保存。 | 同时管理临时文件、项目文件和长期Memory |

## 2.内置backend

### 1.StateBackend

```ts
import { createDeepAgent, StateBackend } from "deepagents";

// 默认使用StateBackend
const agent = createDeepAgent();
// 等价于
const agent2 = createDeepAgent({
  backend: new StateBackend(),
});
```

1. 文件存储在当前线程的state中

2. 通过checkpoint，同一线程上的多个Agent可以共享. 但不能跨线程间共享。

适合:

1. Agent记录中间结果。
2. 将大型Tool输出转存为文件，供Agent分段读取。

注: 此Backend由主Agent与子Agent共享。子Agent写入的文件执行结束后仍保留在State中，主Agent和其他子Agent可以继续访问。

### 2.FilesystemBackend

在指定目录下读写**磁盘文件**，让Agent直接访问本地文件。

**工作原理：**

- Agent可读写`rootDir`目录下的文件。

- **virtualMod: **沙盒模式, 将路径限制在`rootDir`内，阻止访问外部路径。

  默认为`false`, 此时即使设置了`rootDir`，也可以访问外部路径。

- 使用安全路径解析，防止不安全的符号链接跳转。可使用ripgrep进行快速grep.

**适用场景：**

- 本地开发 CLI，如编程助手、开发Tool。
- CI/CD 流水线。

不适用于Web服务器或HTTP API，应改用`StateBackend`、`StoreBackend`或`sandbox`。

**安全风险与防护：**

| 风险                                     | 建议                                              |
| ---------------------------------------- | ------------------------------------------------- |
| Agent可读取任何文件，包括API Key、`.env`| 将敏感文件排除在可访问路径之外，尤其是 CI/CD 环境 |
| 配合网络Tool，可通过SSRF攻击窃取机密信息 | 限制文件与网络访问权限                            |
| 文件修改是永久性的，不可逆。             | 启用HITL，审核敏感操作                            |
| 仅设置根目录不能保证访问限制             | 同时设置`rootDir`并开启`virtualMode`|

生产环境需要文件操作时，建议使用沙箱Backend。

```ts
import { createDeepAgent, FilesystemBackend } from "deepagents";

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new FilesystemBackend({
    rootDir: ".", virtualMode: true})
});
```

**建议将FilesystemBackend封装在CompositeBackend中**, 如果单独使用`FilesystemBackend`，所有文件都会写入到磁盘的root_dir目录中，导致Agent文件与项目文件混杂在一起。使用`CompositeBackend`将项目目录路由到`FilesystemBackend`，将临时文件路由到`StateBackend`：

```ts
import { createDeepAgent, CompositeBackend, FilesystemBackend, StateBackend } from "deepagents";

const agent = createDeepAgent({
  backend: new CompositeBackend(
    // 临时文件保留在State中
    new StateBackend(), 
    //workspace保存到Filesystem中
    {"/workspace/": new FilesystemBackend({
      rootDir: "/path/to/project",
      virtualMode: true,
    }),
  }),
});
```

### 3.StoreBackend

```ts
import { createDeepAgent, StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph";

const store = new InMemoryStore();

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new StoreBackend({
    namespace: () => [rt.serverInfo.user.identity],
  }),
  store,
});
```

**工作原理**

将文件存储在runtime提供的Store中，实现跨线程持久存储。

能否在进程重启后保留数据，取决于Store类型,`InMemoryStore`仅适合本地开发。

**适用场景**

适用于已配置好Store的项目，或部署到LangSmith平台的项目.

部署到LangSmith时，可省略`store`，平台会自动提供。

#### Namespace工厂

namespace工厂用于控制`StoreBackend`读写数据的位置。它接收LangGraph`Runtime`，返回字符串tuple作为存储namespace，用于隔离不同用户的数据。

| Runtime 字段       | 提供的信息                                        |
| ------------------ | ------------------------------------------------- |
|`rt.context`| 通过context传入的数据，如用户 ID |
|`rt.serverInfo`| Server端信息，如助手ID、图ID、已认证用户    |
|`rt.executionInfo`| 执行信息，如线程ID、运行ID、检查点ID           |

```ts
import { StoreBackend } from "deepagents";

// 按用户隔离
const userBackend = new StoreBackend({
  namespace: () => [rt.serverInfo.user.identity],
});

// 按助手隔离：同一助手的所有用户共享
const assistantBackend = new StoreBackend({
  namespace: () => [rt.serverInfo.assistantId],
});

// 按线程隔离
const threadBackend = new StoreBackend({
  namespace: () => [rt.executionInfo.threadId],
});
```

可以组合多个字段进一步细分，例如`(user_id, thread_id)`, 如果同一范围需要多个存储namespace，可以追加`"filesystem"`等后缀来区分。例如

```ts
("user_1", "thread_1", "filesystem")  # 该会话的文件数据
("user_1", "thread_1", "memory")      # 该会话的Memory数据
```

namespace禁止`*`、`?`，防止 glob 注入。

如果没有提供namespace工厂，默认使用元数据中的`assistant_id`。意味着同一助手的所有用户共享一个存储空间。对于多用户场景，务必提供namespace工厂。

### 4.ContextHubBackend

将文件系统保存在 LangSmith Context Hub 仓库中，无需单独配置 LangGraph Store。使用前需配置`LANGSMITH_API_KEY`。

仓库可以是独立仓库，也可以是关联多个Skill仓库的Agent仓库：

- Agent仓库保存`AGENTS.md`、`tools.json`等顶层配置，挂载在文件系统根目录。
- 关联的Skill仓库挂载到`/skills/`下，可独立管理版本，并被多个Agent复用。
- 仓库标识支持`owner/name`或`name`。

工作方式与限制：

- 首次使用时拉取仓库，之后从内存缓存读取。
- 写入和编辑会生成 Hub 提交，成功后更新缓存。
- 使用`parent_commit`检查并发修改；如果其他写入者已推进版本，需要重新拉取并重试。
- 仓库不存在时，首次读取视为空仓库，首次成功写入可创建仓库。
-`upload_files()`只接受 UTF-8 文本，其他编码的文件会逐个返回`invalid_path`。

适合需要持久化文件和提交历史、且主要使用 LangSmith 的工作流。

### 5.LocalShellBackend

```ts
import { createDeepAgent, LocalShellBackend } from "deepagents";

const backend = new LocalShellBackend({ workingDirectory: "." });
const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend,
});
```

工作原理：

- 在`FilesystemBackend`基础上增加`execute`Tool, 以支持在本地运行shell
- 命令直接在本机执行，没有沙箱隔离。
- 支持`timeout`和环境变量配置。
- Shell命令使用`root_dir`作为工作目录，但可访问系统上的任何路径。

**适用于**本地编程助手、可信个人开发环境。

**不适用于**生产环境、或执行未知代码。

**安全风险：**

- 命令会拥有当前用户的权限，执行任意命令, 读取任意文件
- 即使`virtualMode为true`, 也无法隔离文件
- 命令会直接在主机系统上运行

**建议防护措施：**

1. 启用HITL  在执行操作前进行审查和批准。
2. 仅限在专用开发环境中运行。勿在共享系统或生产系统上使用。
3. 对于需要执行shell的生产环境，使用沙箱.

### 6.CompositeBackend

工作原理:

- 根据路径前缀将文件路由到不同的Backend。
- 在列表和搜索结果中保留原始路径前缀。

```ts
const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new CompositeBackend(), {
    "/memories/": new StoreBackend({
      namespace: () => ["memories"],
    }),
  }),
  store: new InMemoryStore(),
});
```

## 3.路由到不同Backend

下面将`/memories/`保存到磁盘，其余路径保留在线程状态中：

```ts
const agent = createDeepAgent({
  backend: new CompositeBackend(
    new StateBackend(),
    {
      "/memories/": new FilesystemBackend({ 
        rootDir: "/deepagents/myagent", 
        virtualMode: true
      }),
    }),
});
```

| 访问路径        | 实际存储位置                            |
| -------------------- | --------------------------------------- |
|`/workspace/plan.md`|`StateBackend`|
|`/memories/agent.md`|`FilesystemBackend`的`/deepagents/myagent/agent.md`|

路由规则：

- **最长前缀匹配策略**：路由`/memories/projects/`可以覆盖`/memories/``
- 路由到`StoreBackend`时，需确保`create_deep_agent(model=..., store=...)`传入了Store。
- 大型Tool结果、对话历史等内部数据写入`默认Backend`。建议默认使用`StateBackend`，以确保这些数据是临时的，避免将其写入磁盘持久存储
