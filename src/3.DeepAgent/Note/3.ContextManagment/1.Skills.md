# Skiils

Skill包将领域专业知识（例如工作流程、脚本、参考文档和模板）打包到可重用的目录中。

Agent在启动时仅读取摘要内容，在任务需要时再读取完整信息, 避免上下文信息过载。可以跨Agent和项目共享Skill，并在单个Agent中组合多个Skill.

## 1.用法

1. 在后端根目录下创建`skills/`目录。

2. 在技能目录下创建一个子目录来存放技能

   每个技能都是一个目录，其中包含一个SKILL.md文件：这是一个 Markdown 文件，其 YAML前言(包含名称和描述)之后是代理在激活技能时需要执行的指令。技能目录还可以选择性地包含辅助文件，例如脚本、参考文档和模板。

   <img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/image-20261011165947048.png" alt="image-20261011165947048" style="zoom:50%;" align='left'/>

3. 添加一个包含 YAML 前置信息和说明的SKILL.md文件。

   SKILL.md文件以YAML前置元数据开头，后跟 Markdown 指令：

   ```yaml
   ---
   name: langgraph-docs
   description: Use this skill for requests related to LangGraph in order to fetch relevant documentation to provide accurate, up-to-date guidance.
   ---
   
   # langgraph-docs
   
   ## Overview
   
   This skill explains how to access LangGraph documentation to help answer questions and guide implementation.
   
   ## Instructions
   
   ### 1. Fetch the documentation index
   
   Use the fetch_url tool to read the following URL:
   https://docs.langchain.com/llms.txt
   
   This provides a structured list of all available documentation with descriptions.
   
   ### 2. Select relevant documentation
   
   Based on the question, identify 2-4 most relevant documentation URLs from the index. Prioritize:
   
   - Specific how-to guides for implementation questions
   - Core concept pages for understanding questions
   - Tutorials for end-to-end examples
   - Reference docs for API details
   
   ### 3. Fetch and synthesize
   
   Use the fetch_url tool to read the selected documentation URLs, then answer the user's question. Give a direct answer first, include the minimum necessary context, and link to the source pages rather than quoting long passages.
   ```

4. 创建Agent时指定Skill路径。

   ```ts
   import { createDeepAgent, FilesystemBackend } from "deepagents";
   
   const backend = new FilesystemBackend({ rootDir: process.cwd() });
   
   const agent = await createDeepAgent({
     model: "anthropic:claude-sonnet-4-6",
     backend,
     skills: ["/skills/"],
   });
   ```

   本示例使用FilesystemBackend从磁盘加载Skill。有关其他存储选项（包括从远程源加载Skill），请参阅后端和远程Skill加载。

   Skill路径必须使用正斜杠 `/`，并且相对于backend的根目录。

   - 使用 `StateBackend`（默认）时，通过 `invoke(files={...})` 提供Skill文件。使用 `deepagents.backends.utils` 中的 `create_file_data()` 格式化文件内容，不支持直接传入原始字符串。
   - 使用 `FilesystemBackend` 和 `StoreBackend` 时，先创建后端，调用 `backend.uploadFiles()` 添加Skill文件，再将后端传给 `createDeepAgent`。对于 `FilesystemBackend`，使用 `virtualMode: true` 将路径限制在 `rootDir` 下。已经存在于 `rootDir` 下的Skill文件无需上传即可加载。

   包含同名Skill时, 位置靠后的优先。这允许你叠加不同来源的Skill，例如用项目专属版本覆盖基础版本。

5. 调用Agent

   启动时，Agent会将每个Skill的名称和描述从frontmatter加载到系统提示符中。当你的任务与某个Skill的描述匹配时，Agent会读取该Skill的SKILL.md 文件并执行其中的指令。

   ```ts
   const result = await agent.invoke(
     { messages: [{ role: "user", content: "What is LangGraph?" }] },
     { configurable: { thread_id: "1" } },
   );
   ```

## 2.Skill如何运作

Skill加载分三个级别, 采用**渐进式加载**, 仅在任务需要时才增加更多细节.

<img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/skills-progressive-disclosure.svg" style="zoom:50%;" />

在 Deep Agents 中，传入 `skills` 后，`SkillsMiddleware` 会作为 Deep Agents 组件栈的一部分处理前两个层级，第三个层级由 LLM 处理：

1. **发现（第 1 层）**：Agent 启动时，中间件扫描配置的Skill路径，解析每个 `SKILL.md` 的文件头，将 `name` 和 `description` 注入系统提示词。
2. **读取（第 2 层）**：Agent 调用Skill时，通过 `read_file` 读取完整的 `SKILL.md` 内容。
3. **执行（第 3 层）**：调用后，Agent 遵循Skill指令，仅在指令要求时读取辅助文件（脚本、参考资料、资源文件）。

## 3.Skill写作技巧

**保持frontmatter简洁: **，将`SKILL.md`正文控制在 5,000 tokens 以内。Agent发现Skill时，每个Skill的`frontmatter`都会加入系统提示词；完整正文在Skill激活后读取。控制这两部分的大小，可以加载更多Skill，避免挤占上下文窗口。

**编写具体的描述:** 在发现阶段，`description` 是 Agent 判断Skill用途的唯一信息。好的描述应说明Skill做什么、何时激活，并包含便于 Agent 匹配的具体关键词。

```yaml
# Good: specific about what and when
description: >-
  Extract text and tables from PDF files, fill PDF forms, and merge
  multiple PDFs. Use when working with PDF documents or when the user
  mentions PDFs, forms, or document extraction.

# Poor: too vague for reliable matching
description: Helps with PDFs.
```

如果多个Skill涉及同一领域，应明确区分它们的描述。描述重叠可能导致 Agent 选错Skill，或在多个选项之间犹豫。同时合并用途相似的Skill。

**保持简单明了** Agent Skills 规范建议将 `SKILL.md` 控制在 500 行以内。指令过长时，将详细参考资料移到辅助资源文件中，并在主 `SKILL.md` 中引用。

Agent 只在指令要求时加载参考文件，让逐步加载的每一层都保持适当大小。参考文件应由`SKILL.md`直接引用，避免层层嵌套，否则 Agent 需要多次读取才能找到所需信息。

**按 Agent 易于执行的方式组织指令：**

- **分步流程**：用于包含多个步骤的工作流。
- **判断标准**：帮助Agent选择不同方案。
- **预期输入和输出示例**：让Agent知道怎样才算成功。
- **边界情况**：说明哪些情况需要处理，哪些需要提醒用户。

**控制Skill数量: ** 少量职责明确的Skill，比大量用途重叠的Skill效果更好。描述相似的Skill越多，Agent越难选对。如果有很多相关Skill，可以：

- 将相关能力合并为一个Skill，用不同章节说明各个子任务。
- 使用参考文件覆盖多个子任务，同时保持主`SKILL.md`简洁。

## 4.辅助资源

除了 `SKILL.md`，Skill目录还可以包含其他文件或目录。Agent Skills 规范定义了三个可选目录，用于存放常见资源。Deep Agents 不会在发现或激活Skill时加载这些文件，只有当 `SKILL.md` 中的指令要求时，Agent 才会读取或执行它们。

### `scripts/`

存放 Agent 可以运行的代码，例如 API 客户端、数据转换脚本或校验程序。脚本应：

- 能独立运行，或明确说明依赖。
- 提供有用的错误信息。
- 妥善处理边界情况。

支持的语言取决于Agent的配置，常见的有 Python、Bash、JavaScript 和 TypeScript。要执行脚本，需要配置相应的代码执行能力；需要 Shell 时，可使用沙箱脚本。

### `references/`

存放 Agent 按需读取的补充文档，适合放置过于详细、不宜写进 `SKILL.md`，但与任务相关的内容，例如：

- `REFERENCE.md`：详细技术参考。
- `FORMS.md`：表单模板或结构化数据格式。
- 领域指南：如 `finance.md`、`legal.md`。

每个参考文件应聚焦一个主题。Agent 只在需要时加载，文件越小，占用的上下文越少。

### `assets/`

存放Agent会使用、但不需要作为指令读取的静态资源，例如：

- 文档或配置模板。
- 图片，如示意图、示例。
- 数据文件，如查找表、数据结构定义。

在 `SKILL.md` 中说明何时应打开或复制每个资源。

### 在 `SKILL.md` 中引用文件

引用辅助文件时，使用相对于Skill根目录的路径：

```yaml
For API details, see the [reference guide](references/api-patterns.md).

To extract tables from a PDF, run:
scripts/extract.py
```

对每个引用的文件，说明它包含什么、何时使用。由 `SKILL.md` 直接引用所需文件，避免层层嵌套，导致 Agent 多次读取才能找到信息。

## 5.后端和远程Skill加载

Deep Agents 支持不同的后端，具体取决于您希望如何存储和管理Skill文件：

- StateBackend：将文件存储在当前线程的 LangGraph Agent状态中。
- StoreBackend：将文件存储在 LangGraph 存储中，以实现持久的跨线程存储。
- FilesystemBackend：从磁盘读取和写入可配置的root_dir下的Skill文件。

## 6.Skill可用性

并非每次运行都需要所有Skill。可控制Agent可以访问哪些Skill。上下文可以来自请求处理程序、身份验证声明、图工厂、部署配置或任何其他应用程序逻辑。

### 根据上下文选择Skill

创建Agent之前，可选择Skill数组。当Skill位于同一位置，并且您的应用程序决定哪些路径适用于当前角色、用户或请求类型时，优先使用此选项：

```ts
import { createDeepAgent } from "deepagents";

const SKILLS_BY_ROLE: Record<string, string[]> = {
  engineering: [
    "/skills/code-review/",
    "/skills/testing/",
    "/skills/deployment/",
  ],
  data: [
    "/skills/sql-analysis/",
    "/skills/visualization/",
    "/skills/data-pipeline/",
  ],
  support: ["/skills/ticket-triage/", "/skills/runbook/"],
};

function createAgentForUser(userRole: string) {
  return createDeepAgent({
    model: "anthropic:claude-sonnet-4-6",
    skills: SKILLS_BY_ROLE[userRole] ?? [],
  });
}
```

这种模式为每个Skill保留一份副本，仅改变传递给每个Agent的路径。在部署过程中，图工厂是解析用户信息并构建具有正确Skill路径的Agent的理想场所。

### 隔离Skill库

当同一个Skill路径需要为不同用户、角色、工作区或环境提供不同文件时，可使用隔离的Skill库。例如，所有 Agent 都配置 `skills=["/skills/"]`，但后端会根据当前身份或部署环境，将 `/skills/` 映射到对应的存储空间。

示例使用 `StoreBackend`，同样的方式也适用于其他能根据运行时上下文解析文件的后端。

```ts
import {
  createDeepAgent,CompositeBackend,StateBackend,StoreBackend
} from "deepagents";

const agent = await createDeepAgent({
  model: "anthropic:claude-sonnet-4-6",
  skills: ["/skills/"],
  backend: new CompositeBackend(new StateBackend(), {
    "/skills/": new StoreBackend({
      namespace: (ctx) => [
        ctx.assistantId ?? "default",
        ctx.config?.configurable?.user_id ?? "anonymous",
      ],
    }),
  }),
});
```

这样可以保持 Agent 配置不变，由后端控制它能访问哪个Skill库。

要填充共享Skill库，可以通过应用代码或管理流程预先写入存储：

- 按组织 ID 划分命名空间，用于工作区共享Skill。如果 Agent 只能使用、不能修改Skill库，应配合只读Skill。
- 按用户 ID 划分命名空间，让每个用户拥有独立Skill库。

写入存储时，键可以是 `/company-policies/SKILL.md`，值需要包含 `content` 和 `encoding` 字段。从存储读取记录前，会移除 `/skills/` 路由前缀。

也可以组合共享和个人Skill库：将 `/skills/approved/` 路由到组织范围的 `StoreBackend`，将 `/skills/editable/` 路由到用户范围的后端，并将两个路径都传入 `skills`。

### 组合多个来源

当 Agent 需要访问多个Skill库时，传入多个路径.

```ts
import { createDeepAgent } from "deepagents";

const agent = await createDeepAgent({
  model: "anthropic:claude-sonnet-4-6",
  skills: ["/skills/org/", "/skills/team/", "/skills/request/"],
});
```

每个路径指向同一个或不同的后端，或根据运行时上下文隔离的后端。Fleet Skill提供托管方案，用于管理Skill访问、共享和工作区内的可见性。

## 7.重新reloadSkill

配置了 checkpointer 时，Skill在每个线程中只加载一次，并保存在 Agent 状态中。后续模型调用会复用同一份列表，之后新增、修改或删除的Skill不会传给模型。

没有 checkpointer 时，状态不会在多次运行之间保留，因此每次运行都会重新加载Skill。

重置已保存的元数据后，下一次模型调用会重新加载所有来源。

> 本地运行通常没有 checkpointer，因此Skill修改会立即生效，看起来像是自动重新加载。LangSmith Deployments 会自动配置持久化 checkpointer，所以部署后，Skill列表会在线程的整个生命周期内保留。

重置时应使用 `null`，不要使用空列表`[]`。空列表表示来源已经加载，但没有任何Skill，因此不会重新加载Skill. 

```ts
const result = await agent.invoke(
  {
    messages: [{ role: "user", content: "What is LangGraph?" }],
    skillsMetadata: null,
  },
  config,
);
```

> 如果重新加载后Skill发生变化，系统提示词也会变化，使该线程的提示词缓存失效。如果Skill相同，生成的提示词也相同，不会产生额外成本。

中间件也可以重置这个值，从而让应用自行决定何时需要刷新线程中的Skill。

加载发生在每次模型调用之前，因此钩子中的重置会在下一次模型调用中生效，包括运行过程中.

```ts
import { createMiddleware } from "langchain";
import { StateSchema } from "@langchain/langgraph";
import { skillsMetadataValue } from "deepagents";

const reloadEditedSkills = createMiddleware({
  name: "ReloadEditedSkills",
  stateSchema: new StateSchema({ skillsMetadata: skillsMetadataValue }),
  afterModel: (state) =>
    agentEditedSkills(state) ? { skillsMetadata: null } : undefined,
});
```

## 8.SubAgent的Skill

使用SubAgent时，可以分别配置它们能访问的Skill：

- **通用SubAgent**：通过`createDeepAgent`继承主Agent的Skill，无需额外配置。
- **自定义SubAgent**：不继承主Agent的Skill。在SubAgent定义中添加`skills`参数，指定Skill路径。

Skill完全隔离：主 Agent 和SubAgent不能互相访问对方的Skill。

```ts
import { createDeepAgent } from "deepagents";

const researchSubagent = {
  name: "researcher",
  description: "Research assistant with specialized skills",
  systemPrompt: "You are a researcher.",
  tools: [webSearch],
  skills: ["/skills/research/", "/skills/web-search/"], // Subagent-specific skills
};

const agent = await createDeepAgent({
  model: "google:gemini-3.6-flash",
  skills: ["/skills/main/"], // Main agent and GP subagent get these
  subagents: [researchSubagent], // Researcher gets only its own skills
});
```

## 9.Skill权限

Skill可用性决定Agent能访问哪些Skill

Skill权限决定能否读取、修改Skill文件，以及修改前是否需要人工批准。

使用文件系统权限配置, 基于路径决定读写规则。需要写入审批时，使用 `interrupt_on` 或 `mode="interrupt"` 的权限规则。

### 只读Skill

Agent可以发现和读取Skill，但不能修改, 只有应用代码或管理员能够更新。

适用于企业知识库、已批准的工具使用指令，以及集中管理的Skill包。

```ts
import { InMemoryStore } from "@langchain/langgraph";
import {
  createDeepAgent,CompositeBackend,StateBackend,StoreBackend
} from "deepagents";

const store = new InMemoryStore(); // Good for local dev; omit for LangSmith Deployment

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  backend: new CompositeBackend(new StateBackend(), {
    "/skills/": new StoreBackend({
      namespace: (rt) => ["curated-skills", rt.context.orgId],
    }),
  }),
  skills: ["/skills/"],
  permissions: [
    {
      operations: ["write"],
      paths: ["/skills/**"],
      mode: "deny",
    },
  ],
  store,
});
```

### 可写Skill

默认情况下，只要后端允许，且没有权限规则阻止，Agent 可以修改Skill文件。

要允许 Agent 创建或完善部分Skill，同时保护其他Skill：

1. 将可写路径路由到能够持久保存修改的后端。
2. 将这些路径传入 `skills`。
3. 对只读路径添加禁止写入的规则。路径重叠时，将更具体的规则放在范围更大的禁止规则之前。

```ts
import { InMemoryStore } from "@langchain/langgraph";
import {
  createDeepAgent, CompositeBackend, StateBackend, StoreBackend
} from "deepagents";

const store = new InMemoryStore(); // Good for local dev; omit for LangSmith Deployment

const agent = await createDeepAgent({
  model: "anthropic:claude-sonnet-4-6",
  backend: new CompositeBackend(new StateBackend(), {
    "/skills/approved/": new StoreBackend({
      namespace: (rt) => ["approved-skills", rt.context.orgId],
    }),
    "/skills/editable/": new StoreBackend({
      namespace: (ctx) => [
        "editable-skills",
        ctx.config?.configurable?.user_id ?? "anonymous",
      ],
    }),
  }),
  skills: ["/skills/approved/", "/skills/editable/"],
  permissions: [
    {
      operations: ["write"],
      paths: ["/skills/approved/**"],
      mode: "deny",
    },
  ],
  store,
});
```

Agent 使用 `write_file` 和 `edit_file` 创建或更新可写路径下的 `SKILL.md` 及辅助文件。

如果要保存Skill格式之外的通用经验，可以将 `/memories/` 等独立路径路由到另一个可写后端。

### 写入审批

如果允许 Agent 修改Skill，但希望先由人工批准，可以使用：

- `interrupt_on`
- `mode="interrupt"` 的权限规则

两者都会在执行 `write_file` 或 `edit_file` 前暂停，并使用相同的恢复流程。

```ts
import { MemorySaver } from "@langchain/langgraph";
import { createDeepAgent } from "deepagents";

const agent = await createDeepAgent({
  model: "anthropic:claude-sonnet-4-6",
  skills: ["/skills/editable/"],
  permissions: [
    {
      operations: ["write"],
      paths: ["/skills/**"],
      mode: "interrupt",
    },
  ],
  checkpointer: new MemorySaver(), // Required to pause and resume
});
```

也可以配置：

```
interrupt_on={"write_file": True, "edit_file": True}
```

这会要求所有文件系统写操作获得批准，而不仅限于Skill路径。

## 10.通过Skill执行代码

没有代码执行能力时，Agent只能读取Skill指令，并通过已有工具完成任务。

加入代码执行能力后，Skill可以调用经过测试的脚本，完成调用 API、转换数据、验证输出或运行处理流程. 直接执行固定逻辑, 无需每次根据指令重新生成代码。

这适用于要求行为精确的工作流，例如数据转换、API 集成、合规检查，或依赖特定库的任务。

Skill通过沙箱脚本执行代码。当需要安装依赖、运行测试、调用命令行工具或操作系统文件时，Agent会运行脚本。

### 沙箱脚本

Skill可以在`SKILL.md`旁附带脚本。并在`SKILL.md`中说明脚本的位置及运行时机。

<img src="http://pic-save-fury.oss-cn-shanghai.aliyuncs.com/uPic/image-20261011165311949.png" alt="image-20261011165311949" style="zoom:50%;" align='left'/>

```yaml
---
name: arxiv-search
description: Search the arXiv preprint repository for research papers. Use when the user asks about academic papers, recent research, or scientific literature.
---

# arxiv-search

Search arXiv for papers matching the user's query.

## Instructions

1. Run `scripts/search.ts` with the user's query as an argument.
2. Parse the results and present them with title, authors, abstract summary, and link.
3. If the user asks for more detail on a specific paper, fetch the full abstract.
```

Agent执行脚本需要Shell，只有沙箱后端提供这种能力。

沙箱后端运行在隔离容器中。无法直接访问沙箱外的Skill文件，因此执行前必须先将文件传入容器。需要自定义中间件完成传输：

- **`before_agent`**：从后端读取Skill文件并上传到沙箱，让 Agent 从开始就能执行脚本。
- **`after_agent`**：从沙箱下载修改过或新建的Skill文件，再写回后端，使修改在多次运行之间保留。

```ts
import { readFile, readdir } from "node:fs/promises";
import { join, posix, relative, resolve } from "node:path";
import { fileURLToPath } from "node:url";

import { createMiddleware } from "langchain";
import { CompositeBackend,createDeepAgent,type FileData,
  LangSmithSandbox,StoreBackend } from "deepagents";
import { InMemoryStore } from "@langchain/langgraph";
import { SandboxClient } from "langsmith/sandbox";

const SKILLS_SHARED_NAMESPACE = ["skills", "builtin"] as const;

function createFileData(content: string): FileData {
  const now = new Date().toISOString();
  return {
    content: content.split("\n"),
    created_at: now,
    modified_at: now,
  };
}

function normalizeSkillsStoreKey(key: string): string {
  const k = String(key);
  if (k.includes("..") || /[*?]/.test(k)) {
    throw new Error(`Invalid key: ${key}`);
  }
  return k.startsWith("/") ? k : `/${k}`;
}

async function walkFiles(dir: string): Promise<string[]> {
  const entries = await readdir(dir, { withFileTypes: true });
  const files: string[] = [];
  for (const entry of entries) {
    const fullPath = join(dir, entry.name);
    if (entry.isDirectory()) {
      files.push(...(await walkFiles(fullPath)));
    } else if (entry.isFile()) {
      files.push(fullPath);
    }
  }
  return files.sort((a, b) => a.localeCompare(b));
}

/** Load canonical skill files from disk into the shared store namespace (run once at deploy).
 *  You can retrieve skills from any source (local filesystem, remote URL, etc.).
 */
async function seedSkillStore(store: InMemoryStore) {
  const moduleDir = resolve(fileURLToPath(new URL(".", import.meta.url)));
  const skillsDir = resolve(moduleDir, "skills");
  const filePaths = await walkFiles(skillsDir);
  for (const filePath of filePaths) {
    const rel = relative(skillsDir, filePath);
    // StoreBackend keys are paths *relative to the routed backend root*.
    // CompositeBackend strips the route prefix (`/skills/`) before delegating,
    // so store keys should look like "/<skillname>/SKILL.md".
    const key = `/${posix.normalize(rel.split("\\").join("/"))}`;
    const content = await readFile(filePath, "utf8");
    await store.put([...SKILLS_SHARED_NAMESPACE], key, createFileData(content));
  }
}

/** Copy shared skill files from the store into the sandbox before each agent run. */
function createSkillSandboxSyncMiddleware(backend: CompositeBackend) {
  return createMiddleware({
    name: "SkillSandboxSyncMiddleware",
    beforeAgent: async (state, runtime) => {
      const store = (runtime as any).store;
      if (!store) {
        throw new Error(
          "Store is required for syncing skills into the sandbox. " +
            "Pass `store` to createDeepAgent and ensure your runtime provides it.",
        );
      }

      const encoder = new TextEncoder();
      const files: Array<[string, Uint8Array]> = [];

      for (const item of await store.search([...SKILLS_SHARED_NAMESPACE])) {
        const normalized = normalizeSkillsStoreKey(String(item.key));
        const data = item.value as FileData;
        // CompositeBackend routes paths and batches uploads to the right backend.
        files.push([
          `/skills${normalized}`,
          encoder.encode(data.content.join("\n")),
        ]);
      }

      if (files.length > 0) await backend.uploadFiles(files);

      return state;
    },
  });
}

async function main() {
  const store = new InMemoryStore();
  await seedSkillStore(store);

  const client = new SandboxClient();
  const lsSandbox = await client.createSandbox();

  const backend = new CompositeBackend(
    new LangSmithSandbox({ sandbox: lsSandbox }),
    {
      "/skills/": new StoreBackend({
        store,
        namespace: () => [...SKILLS_SHARED_NAMESPACE],
      } as any),
    },
  );

  try {
    const agent = await createDeepAgent({
      model: "openai:gpt-5.5",
      backend,
      skills: ["/skills/"],
      store,
      middleware: [createSkillSandboxSyncMiddleware(backend)],
    });

  } finally {
    await client.deleteSandbox(lsSandbox.name);
  }
}

main().catch((err) => {
  console.error(err);
  process.exitCode = 1;
});
```

也可以用相同方式，在执行前载入Skill和记忆，并在执行后将两者同步回存储。

## 11.Q&A

### **Skill未激活**

问题：Agent在未读取技能的SKILL.md的情况下处理任务。

解决方法：

1. **让描述更具体**：说明Skill做什么、何时使用，以及可匹配的关键词。发现阶段，Agent 依据 `description` 选择Skill。
2. **减少Skill重叠**：描述相似可能导致选错或跳过Skill。明确区分描述，或合并相关Skill。
3. **确认路径已传入 `skills`**：Skill只会从创建 Agent 时指定的路径，或SubAgent专属的 `skills` 参数中加载。

### 启动时缺少Skill

问题：系统提示词没有列出某个Skill，或读取 `SKILL.md` 失败。

解决方法：

1. **检查路径**：使用正斜杠 `/`，路径相对于后端根目录。`FilesystemBackend` 的路径相对于 `root_dir`；`StateBackend` 需要通过 `invoke(files={...})` 传入文件，并用 `create_file_data()` 格式化内容。
2. **检查文件头**：`name` 必须与父目录名称一致，并符合 Agent Skills 规范。可以使用 `skills-ref` 校验工具检查格式。
3. **检查文件大小**：发现阶段会跳过超过 10 MB 的 `SKILL.md`。
4. **检查多来源覆盖**：同名Skill以后面的来源为准。后面路径中的旧Skill或空Skill，可能覆盖预期版本。

### Skill修改未生效

问题：新增、修改或删除Skill后，Agent 仍然使用旧版本。

解决方法：Skill每个线程只加载一次。已经运行过的线程需要重置已保存的Skill元数据，才能重新加载。

### 找不到辅助文件

问题：Agent 能读取 `SKILL.md`，但无法访问脚本、参考资料或资源文件。

解决方法：

1. **在 `SKILL.md` 中明确引用**：Agent 不会自动发现辅助文件。说明每个文件的内容和使用时机，使用相对于Skill根目录的路径。
2. **将文件放在Skill目录内**：路径由后端解析，确认文件确实存在于指令指定的位置。
3. **同步到沙箱**：使用沙箱后端时，必须先将容器外的Skill文件复制进去。

### 脚本无法执行

问题：Agent 能读取脚本，但不能运行。

解决方法：读取脚本可以使用任何后端，执行脚本需要沙箱后端。

### SubAgent无法访问Skill

问题：自定义SubAgent看不到主 Agent 使用的Skill。

解决方法：在每个自定义SubAgent定义中添加 `skills` 参数，指定Skill来源路径。通用SubAgent会自动继承 `create_deep_agent` 中配置的Skill。

## 12. 参考

### Skill、记忆与工具

| 对比项   | Skill（Skills）                     | 记忆（Memory）                     | 工具（Tools）                      |
| -------- | ----------------------------------- | ---------------------------------- | ---------------------------------- |
| 用途     | 通过逐步披露发现、按需使用的能力    | 启动时加载的持久上下文             | Agent 可以调用的程序化操作         |
| 加载方式 | Agent 判断相关时才读取              | Agent 启动时加载                   | 每轮都可用                         |
| 格式     | 命名目录中的 `SKILL.md`             | `AGENTS.md` 文件                   | 绑定到 Agent 的函数                |
| 叠加方式 | 先用户、后项目，同名Skill以后者为准 | 先用户、后项目，内容合并           | 创建 Agent 时定义                  |
| 适用情况 | 指令与特定任务相关，且内容可能较多  | 始终相关的上下文，如项目约定、偏好 | 需要程序化操作，或无法访问文件系统 |

这些只是使用建议，并非严格边界。

Agent 可以在工作中更新Skill，记录新流程并完善指令。因此，Skill也可以作为一种按需加载的记忆：Agent 逐渐积累上下文，在需要时读取，而不是每次都加入提示词。

**文件头字段**

Agent Skills 规范定义了以下字段：

| 字段            | 必填 | 说明                                                         |
| --------------- | ---- | ------------------------------------------------------------ |
| `name`          | 是   | 使用小写字母、数字和连字符，长度为 1–64 个字符，必须与父目录名称一致 |
| `description`   | 是   | 说明Skill做什么、何时使用，最多 1,024 个字符                 |
| `license`       | 否   | 许可证名称，或Skill附带的许可证文件引用                      |
| `compatibility` | 否   | 环境要求，如系统软件包、网络访问，最多 500 个字符            |
| `metadata`      | 否   | 用于附加属性的任意键值对                                     |
| `allowed-tools` | 否   | Skill可使用的预先批准工具列表，以空格分隔；属于实验性功能    |

```yaml
---
name: langgraph-docs
description: Use this skill for requests related to LangGraph in order to fetch relevant documentation to provide accurate, up-to-date guidance.
license: MIT
compatibility: Requires internet access for fetching documentation URLs
metadata:
  author: langchain
  version: "1.0"
allowed-tools: fetch_url
---

# langgraph-docs

Instructions for the agent go here. See [Usage](#usage) for a complete example of skill instructions.
```
