# Subagent

SubAgent用于上下文隔离, 保持主Agent的上下文干净.

本节介绍**同步**SubAgent，主Agent会阻塞直到SubAgent完成。对于需要长时间、并行工作或中途控制的情况，可使用**异步SubAgent**.

## 1.适用情况

适合使用Subagent的情况：

- ✅ 多步骤任务会使Main Agent的上下文变得冗杂。
- ✅ 专业领域需要定制指令或工具。
- ✅ 任务需要不同的模型能力。
- ✅ 希望Main Agent专注于高层协调工作。

不适合使用Subagent的情况：

- ❌ 简单的任务。
- ❌ 需要保留中间上下文。
- ❌ 使用Subagent的额外开销超过收益。

## 2.配置

`subagents`应当是一个字典列表, 或一个`CompiledSubAgent`对象。有两种类型:

### 1.默认Subagent

Deep Agents会自动添加一个名为`general-purpose`的同步通用Subagent, 默认具有文件系统工具，也可使用其他工具或中间件。

- 可传入名为 `general-purpose` 的自定义Subagent替换它。

- 要修改自动添加的通用Subagent，在配置中设置：

  ```
  general_purpose_subagent=GeneralPurposeSubagentProfile(...)
  ```

- 要禁用默认Subagent，参阅下一节。

### 2.禁用Subagent

要禁用subagent, 需要做两件事：

1. 在配置中设置：

   ```ts
   import { registerHarnessProfile } from "deepagents";
   
   registerHarnessProfile(
    "openai:gpt-5.4",
    	{
     generalPurposeSubagent: { enabled: false }
   });
   ```

2. 调用`create_deep_agent`时，不传入Subagent。

   ```
   subagents=[]
   ```

只有存在至少一个同步子 Agent，Deep Agents 才会添加 `SubAgentMiddleware` 和 `task` 工具。两种来源都关闭后，主 Agent 就不会通过 `task` 委派任务。

异步Subagent不受影响，它使用独立的中间件和工具.

> **不要用 `excluded_middleware` 排除 `SubAgentMiddleware`**，这样会抛出 `ValueError`；应通过上面的配置关闭。

### 3.自定义Subagent

使用`Subagent`参数定义具有特定工具的专用subagent，例如代码审查员、网络研究员.

大多数情况下，使用符合`SubAgent`的规范进行定义即可。复杂工作流可以使用 `CompiledSubAgent`。

#### SubAgent(基于规范)

| 字段             | 类型                                          | 说明                                                         |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------ |
| `name`           | `string`                                      | **必填:** 唯一标识符。Main Agent调用`task()`工具时使用此名称。该名称也会用于区分Agent。 |
| `description`    | `string`                                      | **必填:** 说明能执行什么操作。Main Agent据此委派任务.        |
| `systemPrompt`   | `string`                                      | **`isolated(默认模式)`模式**时**必填**。用于定义Subagent的指令，应包含工具使用指导和输出格式要求。**不继承Main Agent的Prompt**。 **fork模式**下，除非需要附加说明，否则可省略。 |
| `mode`           | `"isolated" | "fork"`                         | **可选**。默认为 `"isolated"`，Subagent只能看到委派给它的任务。**fork模式**时，会继承父Agent的对话和prompt。 |
| `tools`          | `StructuredTool[]`                            | **可选**。应只包含必要工具。默认继承Main Agent的工具；显式指定后，会**覆盖**继承的工具。 |
| `model`          | `LanguageModelLike | string`                  | **可选**。省略时继承Main Agent的模型。支持模型名，如 `'openai:gpt-5.5'`，格式为 `'provider:model'`；也支持模型对象: `new ChatOpenAI({ model: "gpt-5.5" })` |
| `middleware`     | `AgentMiddleware[]`                           | **可选**。添加中间件，实现自定义行为、日志记录或速率限制。**不会继承Main Agent的中间件**，指定的中间件会追加到Subagent的中间件栈中。 |
| `interruptOn`    | `Record<string, boolean | InterruptOnConfig>` | **可选**。为指定工具配置人工介入。可以设置为 `True`、`False`，或包含 `allowed_decisions` 的 `InterruptOnConfig`。需要配置 `checkpointer`。默认继承Main Agent的配置，Subagent的设置会覆盖默认值。 |
| `skills`         | `string[]`                                    | **可选**。Skill来源路径。指定后，Subagent会从这些目录加载Skill，例如 `["/skills/research/"]`。**不会继承Main Agent的Skill，只有 `general-purpose` Subagent会继承。** 配置Skill的Subagent会运行独立的`SkillsMiddleware` 实例。Subagent的Skill对父Agent不可见，反之亦然。 |
| `responseFormat` | `ResponseFormat`                              | **可选**。设置后，父Agent会以 JSON形式接收结果，而不是文本。支持 Zod schema、JSON Schema 对象、`toolStrategy(...)` 或 `providerStrategy(...)` |
| `permissions`    | `FilesystemPermission[]`                      | **可选**。Subagent的文件系统权限规则。默认继承Main Agent的权限；显式指定后，会**替换**父Agent的权限配置。 |

## 3.Forked Subagent

SubAgent默认以`isolated`模式运行：看不到主Agent的历史数据, 而**Fork Agent**(模式: fork)会继承父Agent的完整对话记录和Prompt。

若SubAgent的任务是继续完成父Agent的工作，可使用该模式。

### 1.配置

将模式设置为`fork`。所有SubAgent字段均可用： 名称、描述、工具、模型等等。

不支持skills参数。可以提供systemPrompt，会附加到继承的prompt中，但通常会破坏Prompt缓存，因此除非有特殊需求，否则不要设置。

[代码地址](https://github.com/INnoVationv2/LangChain-Learn-Note/blob/main/src/3.DeepAgent/Code/4.Delegation/1.Subagents.test.ts#L51)

### 2.工作原理

ForkAgent继承父Agent的对话，不会收到新的任务描述。末尾的委派调用会被替换为任务说明，表明这是对已有对话的继续。完成后，Fork Agent的回答作为普通工具结果返回，父Agent从原处继续执行。

```json
// What the parent has, right before delegating
[
  new HumanMessage("Review the changes in PR #482"),
  new AIMessage({ content: "", tool_calls: [{ name: "read_diff", args: { path: "src/auth/session.py" } }] }),
  new ToolMessage({ content: "- session tokens are logged in plaintext\n- no expiry check on refresh", tool_call_id: "1" }),
  new AIMessage("Found two issues: session tokens are logged in plaintext, and there's no expiry check on refresh."),
  new HumanMessage("Good catch. Draft review comments for those."),
  new AIMessage({ content: "", tool_calls: [{ name: "task", args: { subagentType: "comment-writer", description: "Draft review comments for the two issues found above." } }] }),
]

// What the fork actually sees
[
  new HumanMessage("Review the changes in PR #482"),
  new AIMessage({ content: "", tool_calls: [{ name: "read_diff", args: { path: "src/auth/session.py" } }] }),
  new ToolMessage({ content: "- session tokens are logged in plaintext\n- no expiry check on refresh", tool_call_id: "1" }),
  new AIMessage("Found two issues: session tokens are logged in plaintext, and there's no expiry check on refresh."),
  new HumanMessage("Good catch. Draft review comments for those."),
  new HumanMessage("Continuing as the subagent that was just invoked. Draft review comments for the two issues found above."),
]
```

fork子代理沿用父代理相同的提示词前缀，因此可以复用父代理的 prompt cache，减少重复处理输入的耗时和成本。

但如果子代理调用了不同的工具，或工具返回内容不同，输入就会从那里开始产生差异，**不同的部分无法命中缓存**；前面相同的部分可以复用。

这里缓存的是提示词的处理结果，不是直接复用父代理的回答。

`CompiledSubAgent`也支持fork，但由于该graph已经构建完成，会保留自己的Prompt。

### 3.何时使用

| 维度                 | 隔离模式（默认）             | Fork模式                                                     |
| -------------------- | ---------------------------- | ------------------------------------------------------------ |
| **Context**          | 仅包含传入的任务描述         | 包含父Agent的完整对话历史和Prompt                            |
| **Prompt和Skill**    | 可以为SubAgent单独设置       | 无法设置Skill；Prompt会追加到父Agent的Prompt后面（会破坏缓存，通常不设置） |
| **调用其他SubAgent** | 可以使用 `task` 工具         | 无法使用 `task`，必须自行完成工作                            |
| **适用场景**         | 无需太多背景知识的专注型工作 | 继续父Agent已经开始的任务                                    |

## 4.动态SubAgent

主Agent调用`task`工具将任务委派给SubAgent，也可一次发起多个调用，让其并行运行

接入[解释器](https://docs.langchain.com/oss/javascript/deepagents/interpreters)后，Agent可以通过**代码**调度SubAgent：使用循环、分支和并行处理，将工作分配给多个任务项，并通过程序汇总结果。这就是**动态SubAgent**。

当工作涉及大量独立任务(例如审查目录中的每个文件、批量分流工单)时，可以使用动态SubAgent。

### 启用动态SubAgent

只要Agent同时配置了SubAgent和解释器中间件，就可以使用动态SubAgent。

安装 QuickJS 解释器包，然后将 `CodeInterpreterMiddleware` 添加到Agent中。

```ts
import { createDeepAgent } from "deepagents";
import { createCodeInterpreterMiddleware } from "@langchain/quickjs";

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  subagents: [{
    name: "reviewer",
    description: "Reviews code for security issues, citing lines and severity",
    systemPrompt: "You are a security-focused code reviewer. Report issues with line numbers and severity.",
  }],
  middleware: [createCodeInterpreterMiddleware()],
});
```

### 触发动态编排

Agent会根据任务决定是否通过代码分派工作，无需为每次调用设置开关。

> **`workflow` 是触发动态编排的关键词。** 内置提示词会引导Agent通过解释器执行代码，用 `task()` 分派SubAgent任务。
>
> 需要通过代码分派多个任务时，在请求中加入 `workflow`；只需直接委派单个任务时，正常描述即可。

```ts
const result = await agent.invoke({
  messages: [{
    role: "user",
    content: "Run a workflow that reviews every file in src/routes/ and summarizes the top risks."
  }]
});
```

### 在编程Agent中使用

`dcode` 是基于 Deep Agent 的 LangChain 终端编程Agent，默认启用代码解释器，可直接使用动态SubAgent。

安装：

```
curl -LsSf https://langch.in/dcode | bash
```

运行：

```
dcode
```

请求示例：

```
Run a workflow to review every file in src/ for SQL injection.
```

Agent会编写编排脚本，在解释器中调用内置的 `task()`。`dcode`会实时显示SubAgent，并按每次调度划分阶段。

也可以通过 ACP，在Zed等其他编程Agent中使用动态SubAgent。

## 5.Streaming

### 流式获取SubAgent进度

Deep Agents 支持流式获取主Agent和各个SubAgent的更新。

`streamEvents` 提供独立迭代器，分别读取SubAgent、消息、工具调用和状态值。

遍历 `stream.subagents`，可以跟踪任务的启动、执行和完成。每个SubAgent句柄都提供：`.name`、`.messages`、`.tool_calls`和`.output`。

## 6.结构化输出

SubAgent支持结构化输出，让父Agent收到可解析的 JSON。

在SubAgent配置中设置 `responseFormat`，支持：Zod schema, JSON Schema 对象, `toolStrategy(...)`, `providerStrategy(...)`

完成后，结果会序列化为JSON，通过`ToolMessage.content`返回给父Agent。

不配置时，返回SubAgent最后一条消息的原始文本；

```ts
import { z } from "zod";
import { createDeepAgent } from "deepagents";
import { tool } from "langchain";

const webSearch = tool(
  async ({ query }: { query: string }) => `web results for ${query}`,
  {
    name: "web_search",
    description: "Search the web",
    schema: z.object({ query: z.string() }),
  },
);

const ResearchFindings = z.object({
  summary: z.string().describe("Summary of findings"),
  confidence: z.number().describe("Confidence score from 0 to 1"),
  sources: z.array(z.string()).describe("List of source URLs"),
});

const researchSubagent = {
  name: "researcher",
  description: "Researches topics and returns structured findings",
  systemPrompt: "Research the given topic thoroughly. Return your findings.",
  tools: [webSearch],
  responseFormat: ResearchFindings,
};

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  subagents: [researchSubagent],
});

const result = await agent.invoke({
  messages: [
    { role: "user", content: "Research recent advances in quantum computing" },
  ],
});
```

## 7.通用SubAgent

每个Deep Agent默认有一个`general-purpose`SubAgent，它：

- 使用自己的默认Prompt，并应用 profile 配置覆盖。
- 使用与主Agent相同的工具和模型
- 继承主Agent的Skill。

### 覆盖通用SubAgent

在 `subagents` 中添加`name: "general-purpose"`的配置，就会替换默认通用SubAgent，可自行设置模型、工具和Prompt。

```ts
import { createDeepAgent } from "deepagents";
import { tool } from "langchain";
import { z } from "zod";

const internetSearch = tool(
  async ({ query }: { query: string }) => `search results for ${query}`,
  {
    name: "internet_search",
    description: "Run a web search",
    schema: z.object({ query: z.string() }),
  },
);

const agent = await createDeepAgent({
  model: "openai:gpt-5.5",
  tools: [internetSearch],
  subagents: [
    {
      name: "general-purpose",
      description: "General-purpose agent for research and multi-step tasks",
      systemPrompt: "You are a general-purpose assistant.",
      tools: [internetSearch],
      model: "openai:gpt-5.5",
    },
  ],
});
```

若要彻底禁用而不是替换，将当前 harness profile中通用SubAgent的`enabled`标志设为 `False`。

### 使用场景

需要隔离上下文、无需专门定制行为的复杂任务。中间工具调用留在SubAgent内部，主Agent只收到精简结果。

例如，把多次搜索交给通用SubAgent：

```
task(name="general-purpose", task="研究量子计算趋势")
```

SubAgent完成搜索后，仅返回摘要。

### Skill继承

| SubAgent类型   | Skill来源                            |
| -------------- | ------------------------------------ |
| 通用SubAgent   | 自动继承主Agent的Skill               |
| 自定义SubAgent | 默认不继承，需通过 `skills` 单独配置 |

## 9.多个专业SubAgent人

为不同领域创建专门的SubAgent：

```ts
import { createDeepAgent } from "deepagents";

const subagents = [
  {
    name: "data-collector",
    description: "Gathers raw data from various sources",
    systemPrompt: "Collect comprehensive data on the topic",
    tools: [webSearch, apiCall, databaseQuery],
  },
  {
    name: "data-analyzer",
    description: "Analyzes collected data for insights",
    systemPrompt: "Analyze data and extract key insights",
    tools: [statisticalAnalysis],
  },
  {
    name: "report-writer",
    description: "Writes polished reports from analysis",
    systemPrompt: "Create professional reports from insights",
    tools: [formatDocument],
  },
];

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  systemPrompt:
    "You coordinate data analysis and reporting. Use subagents for specialized tasks.",
  subagents: subagents,
});
```

**工作流程：**

1. 主Agent人制定高层计划
2. 将数据收集工作委托给数据收集员
3. 将结果传递给数据分析器
4. 向报告撰写人发送见解
5. 编译最终输出

每个SubAgent都在专注于自身任务的清晰上下文中工作。

## 10.上下文管理

父Agent拥有的`Context`会自动传给所有SubAgent。SubAgent的工具也能访问这些值。

### 读取父AgentContext值

```ts
const getUserData = tool(
    async (input, runtime: ToolRuntime<unknown, typeof contextSchema>) => {
        // Access Main Agent's Context
        const userId = runtime.context?.userId;
        return 'Data for user ${userId}: ${input.query}';
    },
    {
        name: "get_user_data",
        description: "Fetch data for the current user",
        schema: z.object({query: z.string()}),
    },
);
```

### 获取工具调用者

父SubAgent共用工具时，可通过`runtime.config`中的 `lc_agent_name` 判断调用者。

```ts
const sharedLookup = tool(
  async (input, runtime: ToolRuntime) => {
    // 获取调用Tool的Agent name
    const agentName = runtime.config?.metadata?.lc_agent_name;
    console.log(agentName);
  },
  {
    name: "shared_lookup",
    description: "Look up information from various sources",
    schema: z.object({ query: z.string() }),
  },
);
```

## 11.故障排除

### 1.未调用SubAgent

**问题: **主Agent自己执行任务，没有委派给SubAgent。

**解决方法：** 

1. 让描述更具体：

   ```ts
   // ✅ 好的描述
   const goodDescription = {
     name: "research-specialist",
     description:
       "使用网络搜索对特定主题开展深入研究。当你需要通过多次搜索获取详细信息时使用。",
   };
   
   // ❌ 不好的描述
   const badDescription = {
     name: "helper",
     description: "帮忙做点事情",
   };
   ```

2. 明确要求主Agent委派任务：

   ```ts
   import { createDeepAgent } from "deepagents";
   
   const agent = createDeepAgent({
     systemPrompt: `……你的指令……
   
     重要：对于复杂任务，使用 task() 工具将任务委派给SubAgent。
     这样可以保持上下文精简，并改善结果。`,
     subagents: [
       {
         name: "research-agent",
         description: "开展研究",
         systemPrompt: "你是一名研究员。",
       },
     ],
   });
   ```

### 2.上下文冗余

**问题：** 使用SubAgent后，上下文仍被填满。

**解决方法：**

1. 要求SubAgent返回简洁结果：

   ```ts
   const systemPrompt = `...
   
   IMPORTANT: Return only the essential summary.
   Do NOT include raw data, intermediate search results, or detailed tool outputs.
   Your response should be under 500 words.`;
   ```

2. 使用文件系统保存大量数据：

   ```ts
   const filesystemPrompt = `收集大量数据时：
   1. 将原始数据保存到 /data/raw_results.txt
   2. 处理并分析数据
   3. 只返回分析摘要
   
   这样可以保持上下文精简。`;
   ```

### 3.选错SubAgent

**问题：** 主Agent调用了不适合当前任务的SubAgent。

**解决方法：** 在描述中明确区分各个SubAgent：

```ts
const subagents = [
  {
    name: "quick-researcher",
    description:
      "处理只需 1～2 次搜索的简单研究问题。需要基本事实或定义时使用。",
    systemPrompt: "你是 quick-researcher SubAgent。",
  },
  {
    name: "deep-researcher",
    description:
      "处理需要多次搜索、信息整合和分析的复杂深入研究。需要综合报告时使用。",
    systemPrompt: "你是 deep-researcher SubAgent。",
  },
];
```
