可以在` subagents`参数中自定义SubAgent。SubAgent可用于上下文隔离, 保持主代理的上下文干净, 以及提供专门的指令。

这里介绍**同步**SubAgent，主Agent会阻塞直到SubAgent完成。对于长时间、需要并行工作或中途控制和取消的情况，可使用**异步SubAgent**.

## 1.何时使用Subagent

Subagent可以解决上下文膨胀的问题, 适合使用Subagent的情况：

- ✅ 多步骤任务会使Main Agent的上下文变得冗杂。
- ✅ 专业领域需要定制指令或工具。
- ✅ 任务需要不同的模型能力。
- ✅ 希望Main Agent专注于高层协调。

不适合使用Subagent的情况：

- ❌ 简单的单步骤任务。
- ❌ 需要保留中间上下文。
- ❌ 使用Subagent的额外开销超过收益。

## 2.配置

`subagents`应当是一个字典列表, 或`CompiledSubAgent`对象。分两种:

### 1.默认Subagent

Deep Agents会自动添加一个名为`general-purpose`的同步通用Subagent，除非提供同名的同步Subagent。

通用Subagent默认具有文件系统工具，也可以使用其他工具或中间件。

- 要替换它，传入自定义的名为 `general-purpose` 的Subagent。

- 要修改自动添加的通用Subagent，在配置中设置：

  ```
  general_purpose_subagent=GeneralPurposeSubagentProfile(...)
  ```

- 要禁用它，参阅下面这节。

### 2.不使用Subagent运行

要让Agent在没有 `task` 工具的情况下运行，需要完成两件事：

1. 在配置中设置：

   ```
   general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)
   ```

2. 调用 `create_deep_agent` 时，不通过 `subagents=` 传入任何同步Subagent。

只有至少存在一个同步Subagent时，Deep Agents 才会添加 `SubAgentMiddleware` 和 `task`工具。如果既没有默认Subagent，也没有调用方提供的Subagent，Agent会在无Subagent的情况下运行。

异步Subagent不受影响，它使用独立的中间件和工具，详见**异步Subagent**。

> 不要使用`excluded_middleware`来实现这一点。`SubAgentMiddleware` 属于必需的基础组件，将它列入排除列表会引发 `ValueError`。受支持的方式是：
>
> ```
> general_purpose_subagent.enabled = False
> ```

### 3.自定义Subagent

通过`subagents`参数，可以自定义Subagent，例如代码审查员、网络研究员.

大多数情况下，使用符合`SubAgent`规范的字典定义Subagent即可。复杂工作流可以使用 `CompiledSubAgent`。

#### SubAgent（基于字典）

将SubAgent定义为符合SubAgent规范的字典，包含以下字段：

| 字段             | 类型                                          | 说明                                                         |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------ |
| `name`           | `string`                                      | **必填。** Subagent的唯一标识符。Main Agent调用`task()` 工具时使用此名称。该名称也会成为 `AIMessage` 和流式输出的元数据，用于区分Agent。 |
| `description`    | `string`                                      | **必填。** 描述Subagent的职责，明确说明能执行什么操作。Main Agent据此决定委派任务. |
| `systemPrompt`   | `string`                                      | 当`mode: "isolated"(默认模式)` 时**必填**。用于定义Subagent的指令，应包含工具使用指导和输出格式要求。**不继承Main Agent的系统提示词**。 `mode: "fork"`模式下，除非需要仅针对 fork SubAgent的附加说明，否则可省略此字段。参见`Forked Subagent`。 |
| `mode`           | `"isolated" | "fork"`                         | 可选。上下文模式，默认为 `"isolated"`，Subagent只能看到委派给它的任务。设置为`"fork"`时，会继承父Agent的对话和系统提示词。 |
| `tools`          | `StructuredTool[]`                            | 可选。Subagent可使用的工具，应只包含必要工具。默认继承Main Agent的工具；显式指定后，会**完全覆盖**继承的工具。 |
| `model`          | `LanguageModelLike | string`                  | 可选。指定SubAgent模型；省略时继承Main Agent的模型。可以传入模型标识字符串，如 `'openai:gpt-5.5'`，格式为 `'provider:model'`；也可以传入聊天模型对象:  `new ChatOpenAI({ model: "gpt-5.5" })`。 |
| `middleware`     | `AgentMiddleware[]`                           | 可选。添加中间件，实现自定义行为、日志记录或速率限制。**不会继承Main Agent的中间件**，指定的中间件会追加到同步Subagent的中间件栈中。 |
| `interruptOn`    | `Record<string, boolean | InterruptOnConfig>` | 可选。为指定工具配置人工介入。可以设置为 `True`、`False`，或包含 `allowed_decisions` 的 `InterruptOnConfig`。需要配置 `checkpointer`。默认继承Main Agent的配置，Subagent的设置会覆盖默认值。 |
| `skills`         | `string[]`                                    | 可选。技能来源路径。指定后，Subagent会从这些目录加载技能，例如 `["/skills/research/", "/skills/web-search/"]`，从而使用与Main Agent不同的技能集。**不会继承Main Agent的技能，只有 `general-purpose` Subagent会继承。** 配置技能的Subagent会运行独立的 `SkillsMiddleware` 实例。技能状态完全隔离：Subagent已加载的技能对父Agent不可见，反之亦然。 |
| `responseFormat` | `ResponseFormat`                              | 可选。Subagent的结构化输出模式。设置后，父Agent会以 JSON 形式接收结果，而不是自由文本。支持 Zod schema、JSON Schema 对象、`toolStrategy(...)` 或 `providerStrategy(...)`。参见“结构化输出”。 |
| `permissions`    | `FilesystemPermission[]`                      | 可选。Subagent的文件系统权限规则。默认继承Main Agent的权限；显式指定后，会**完全替换**父Agent的权限配置。 |

#### CompiledSubAgent

对于复杂工作流，可使用预先构建的LangGraph图作为`CompiledSubAgent`：

| 字段          | 类型                  | 说明                                                         |
| ------------- | --------------------- | ------------------------------------------------------------ |
| `name`        | `str`                 | **必填。** Subagent的唯一标识符。                            |
| `description` | `str`                 | **必填。** 描述Subagent的职责。                              |
| `runnable`    | `Runnable`            | **必填。** 已编译的 LangGraph 图，必须先调用 `.compile()`。  |
| `mode`        | `"isolated" | "fork"` | 可选，默认为 `"isolated"`。 `"fork"` 模式会继承父Agent的消息历史。无论使用哪种模式，已编译的图都保留自己的系统提示词。参见**Forked Subagent**。 |

## 5.Forked Subagent

SubAgent默认以`isolated`模式运行：看不到主Agent的历史数据, 而**Fork Agent**(模式：“fork”)会继承父代理的完整对话记录和系统提示信息。

当SubAgent的任务是继续完成父代理的工作时，可使用Forked SubAgent。

### 配置

将子代理的模式设置为`fork`。所有子代理字段均可用： 名称、描述、工具、模型等等。

如果提供了skills 参数，则会被拒绝。可以提供systemPrompt，会作为附加信息添加到父进程继承的提示符中，但这样做通常会破坏Prompt缓存，因此除非有特殊需求，否则不要设置它。

[代码地址](https://github.com/INnoVationv2/LangChain-Learn-Note/blob/main/src/3.DeepAgent/Code/4.Delegation/1.Subagents.test.ts#L51)

### 工作原理

分叉代理直接继承父代理的对话，不会收到新的任务描述。末尾的委派调用会被替换为简短说明，表明这是对已有对话的继续。完成后，Fork Agent的回答作为普通工具结果返回，父代理从原处继续执行。

```json
// What the parent has, right before delegating
[
  new HumanMessage("Review the changes in PR #482"),
  new AIMessage({ content: "", tool_calls: [{ name: "read_diff", args: { path: "src/auth/session.py" } }] }),
  new ToolMessage({ content: "- session tokens are logged in plaintext\n- no expiry check on refresh", tool_call_id: "1" }),
  new AIMessage("Found two issues: session tokens are logged in plaintext, and there's no expiry check on refresh."),
  new HumanMessage("Good catch. Draft review comments for those."),
  new AIMessage({ content: "", tool_calls: [{ name: "task", args: { subagentType: "comment-writer", description: "Draft review comments for the two issues found above." } }] }),
]

// What the fork actually sees
[
  new HumanMessage("Review the changes in PR #482"),
  new AIMessage({ content: "", tool_calls: [{ name: "read_diff", args: { path: "src/auth/session.py" } }] }),
  new ToolMessage({ content: "- session tokens are logged in plaintext\n- no expiry check on refresh", tool_call_id: "1" }),
  new AIMessage("Found two issues: session tokens are logged in plaintext, and there's no expiry check on refresh."),
  new HumanMessage("Good catch. Draft review comments for those."),
  new HumanMessage("Continuing as the subagent that was just invoked. Draft review comments for the two issues found above."),
]
```

复用父代理完全相同的前缀，也意味着分叉代理可以复用父代理的提示词缓存，无需从零开始。不过，如果工具调用与父代理不同，仍然会导致缓存未命中。

CompiledSubAgent也支持`mode: "fork"`，但由于其图已经构建完成，会保留自己的系统提示词。

### 何时使用Fork

| 维度                 | 隔离模式（默认）             | 分叉模式                                                     |
| -------------------- | ---------------------------- | ------------------------------------------------------------ |
| **上下文**           | 仅包含传入的任务描述         | 包含父代理的完整对话历史和系统提示词                         |
| **系统提示词与技能** | 可以为子代理单独设置         | 无法设置技能；系统提示词会追加到父代理的提示词后面（会破坏缓存，因此通常不设置） |
| **调用其他子代理**   | 可以使用 `task` 工具         | 无法使用 `task`，必须自行完成工作                            |
| **适用场景**         | 所需历史上下文较少的专项任务 | 继续父代理已经开始的调查                                     |

## 6.动态子代理

默认情况下，主代理通过调用`task`工具将任务委派给子代理，也可以在一轮中发起多个调用，让它们并行运行。

接入[解释器](https://docs.langchain.com/oss/javascript/deepagents/interpreters)后，代理可以通过**代码**调度子代理：使用循环、分支和并行批次，将工作分配到多个任务项，并通过程序汇总结果。这称为[动态子代理](https://docs.langchain.com/oss/javascript/deepagents/dynamic-subagents)。

当工作涉及大量独立任务（例如审查目录中的每个文件、批量分流工单）、需要多个视角，或适合递归分析时，可以使用动态子代理。

### 启用动态子代理

只要代理同时配置了子代理和解释器中间件，就可以使用动态子代理。

安装 QuickJS 解释器包，然后将 `CodeInterpreterMiddleware` 添加到代理中。

```ts
import { createDeepAgent } from "deepagents";
import { createCodeInterpreterMiddleware } from "@langchain/quickjs";

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  subagents: [{
    name: "reviewer",
    description: "Reviews code for security issues, citing lines and severity",
    systemPrompt: "You are a security-focused code reviewer. Report issues with line numbers and severity.",
  }],
  middleware: [createCodeInterpreterMiddleware()],
});
```

### 触发动态编排

代理会根据任务决定是否通过代码分派工作，无需为每次调用设置开关。

> **`workflow` 是触发动态编排的关键词。** 内置提示词会引导代理通过解释器执行代码，用 `task()` 分派子代理任务。
>
> 需要通过代码分派多个任务时，在请求中加入 `workflow`；只需直接委派单个任务时，正常描述即可。

```ts
const result = await agent.invoke({
  messages: [{
    role: "user",
    content: "Run a workflow that reviews every file in src/routes/ and summarizes the top risks."
  }]
});
```

### 在编程代理中使用

`dcode` 是基于 Deep Agent 的 LangChain 终端编程代理，默认启用代码解释器，可直接使用动态子代理。

安装：

```
curl -LsSf https://langch.in/dcode | bash
```

运行：

```
dcode
```

请求示例：

```
Run a workflow to review every file in src/ for SQL injection.
```

代理会编写编排脚本，在解释器中调用内置的 `task()`。`dcode`会实时显示子代理，并按每次调度划分阶段。

也可以通过 ACP，在Zed等其他编程代理中使用动态子代理。

## 7.Streaming

### 流式获取子代理进度

Deep Agents 支持流式获取主代理和各个子代理的更新。

`streamEvents` 提供独立迭代器，分别读取子代理、消息、工具调用和状态值。

遍历 `stream.subagents`，可以跟踪任务的启动、执行和完成。每个子代理句柄都提供：`.name`、`.messages`、`.tool_calls`和`.output`。

## 8.结构化输出

子代理支持结构化输出，让父代理收到可解析的 JSON。

在子代理配置中设置 `responseFormat`，支持：Zod schema, JSON Schema 对象, `toolStrategy(...)`, `providerStrategy(...)`

完成后，结果会序列化为JSON，通过`ToolMessage.content`返回给父代理。

不配置时，返回子代理最后一条消息的原始文本；

```ts
import { z } from "zod";
import { createDeepAgent } from "deepagents";
import { tool } from "langchain";

const webSearch = tool(
  async ({ query }: { query: string }) => `web results for ${query}`,
  {
    name: "web_search",
    description: "Search the web",
    schema: z.object({ query: z.string() }),
  },
);

const ResearchFindings = z.object({
  summary: z.string().describe("Summary of findings"),
  confidence: z.number().describe("Confidence score from 0 to 1"),
  sources: z.array(z.string()).describe("List of source URLs"),
});

const researchSubagent = {
  name: "researcher",
  description: "Researches topics and returns structured findings",
  systemPrompt: "Research the given topic thoroughly. Return your findings.",
  tools: [webSearch],
  responseFormat: ResearchFindings,
};

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  subagents: [researchSubagent],
});

const result = await agent.invoke({
  messages: [
    { role: "user", content: "Research recent advances in quantum computing" },
  ],
});
```

## 9.通用子代理

每个Deep Agent默认有一个`general-purpose`子代理，它：

- 使用自己的默认系统提示词，并应用 profile 配置覆盖。
- 使用与主代理相同的工具和模型
- 继承主代理的技能。

### 覆盖通用子代理

在 `subagents` 中添加`name: "general-purpose"`的配置，就会替换默认通用子代理，可自行设置模型、工具和系统提示词。

```ts
import { createDeepAgent } from "deepagents";
import { tool } from "langchain";
import { z } from "zod";

const internetSearch = tool(
  async ({ query }: { query: string }) => `search results for ${query}`,
  {
    name: "internet_search",
    description: "Run a web search",
    schema: z.object({ query: z.string() }),
  },
);

const agent = await createDeepAgent({
  model: "openai:gpt-5.5",
  tools: [internetSearch],
  subagents: [
    {
      name: "general-purpose",
      description: "General-purpose agent for research and multi-step tasks",
      systemPrompt: "You are a general-purpose assistant.",
      tools: [internetSearch],
      model: "openai:gpt-5.5",
    },
  ],
});
```

若要彻底禁用而不是替换，将当前 harness profile中通用子代理的`enabled`标志设为 `False`。

### 使用场景

需要隔离上下文、无需专门定制行为的复杂任务。中间工具调用留在子代理内部，主代理只收到精简结果。

例如，把多次搜索交给通用子代理：

```
task(name="general-purpose", task="研究量子计算趋势")
```

子代理完成搜索后，仅返回摘要。

### Skill继承

| 子代理类型   | 技能来源                             |
| ------------ | ------------------------------------ |
| 通用子代理   | 自动继承主代理的技能                 |
| 自定义子代理 | 默认不继承，需通过 `skills` 单独配置 |

## 11.多个专业子代理人

为不同领域创建专门的子代理：

```ts
import { createDeepAgent } from "deepagents";

const subagents = [
  {
    name: "data-collector",
    description: "Gathers raw data from various sources",
    systemPrompt: "Collect comprehensive data on the topic",
    tools: [webSearch, apiCall, databaseQuery],
  },
  {
    name: "data-analyzer",
    description: "Analyzes collected data for insights",
    systemPrompt: "Analyze data and extract key insights",
    tools: [statisticalAnalysis],
  },
  {
    name: "report-writer",
    description: "Writes polished reports from analysis",
    systemPrompt: "Create professional reports from insights",
    tools: [formatDocument],
  },
];

const agent = createDeepAgent({
  model: "openai:gpt-5.5",
  systemPrompt:
    "You coordinate data analysis and reporting. Use subagents for specialized tasks.",
  subagents: subagents,
});
```

**工作流程：**

1. 主代理人制定高层计划
2. 将数据收集工作委托给数据收集员
3. 将结果传递给数据分析器
4. 向报告撰写人发送见解
5. 编译最终输出

每个子代理都在专注于自身任务的清晰上下文中工作。

## 12.上下文管理

父代理拥有的`Context`会自动传给所有子代理。子代理的工具也能访问这些值。

### 获取工具调用者

父代理和多个子代理共用工具时，可通过 `runtime.config` 元数据中的 `lc_agent_name` 判断调用者。

```ts
const sharedLookup = tool(
  async (input, runtime: ToolRuntime) => {
    const agentName = runtime.config?.metadata?.lc_agent_name;
    if (agentName === "fact-checker") {
      return strictLookup(input.query);
    }
    return generalLookup(input.query);
  },
  {
    name: "shared_lookup",
    description: "Look up information from various sources",
    schema: z.object({ query: z.string() }),
  },
);
```

结合 `runtime.context` 中的专属配置，就能让工具根据不同代理执行不同逻辑。

结合这两种模式——在分支工具行为时，从runtime.context读取代理特定设置，并从runtime.config元数据读取lc_agent_name 。

```ts
import { tool } from "langchain";
import type { ToolRuntime } from "@langchain/core/tools";
import { z } from "zod";

const contextSchema = z.object({
  userId: z.string(),
  researcherMaxDepth: z.number().optional(),
  factCheckerStrictMode: z.boolean().optional(),
});

const flexibleSearch = tool(
  async (input, runtime: ToolRuntime<unknown, typeof contextSchema>) => {
    const agentName = runtime.config?.metadata?.lc_agent_name ?? "unknown";
    const ctx = runtime.context;
    const maxResults =
      agentName === "researcher" ? (ctx?.researcherMaxDepth ?? 5) : 5;
    const includeRaw = false;

    return performSearch(input.query, { maxResults, includeRaw });
  },
  {
    name: "flexible_search",
    description: "Search with agent-specific settings",
    schema: z.object({ query: z.string() }),
  },
);
```
